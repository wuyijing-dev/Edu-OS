## 🎯 核心概念

### 1. 为什么需要内存管理？

**问题**：
- 物理内存有限（例如128MB）
- 多个程序同时运行
- 如何隔离进程？
- 如何保护内核？
- 如何支持大于物理内存的程序？

**解决方案**：虚拟内存

```
应用程序视角（虚拟地址）：
┌─────────────────┐ 0xFFFFFFFF
│   内核空间      │ (1GB, 高地址)
├─────────────────┤ 0xC0000000
│   用户栈        │
│       ↓         │
│                 │
│       ↑         │
│   用户堆        │
│   .bss/.data    │
│   .text         │
└─────────────────┘ 0x00000000

实际物理内存：
┌─────────────────┐ 物理地址
│  空闲内存       │
├─────────────────┤
│  进程B页面      │
├─────────────────┤
│  进程A页面      │
├─────────────────┤
│  内核          │
└─────────────────┘ 0x00000000
```

### 2. x86分页机制

#### A. 分页单位

```
页（Page）：
- 大小：4KB (4096字节)
- 对齐：必须4KB对齐
- 页号：地址 / 4096

为什么是4KB？
- 平衡内存碎片和页表大小
- CPU硬件支持
- 历史原因（4KB = 2^12）
```

#### B. 两级页表结构

x86使用二级页表系统：

```
虚拟地址（32位）结构：
┌──────────┬──────────┬────────────────┐
│  31-22   │  21-12   │     11-0       │
│  (10位)  │  (10位)  │    (12位)      │
└──────────┴──────────┴────────────────┘
     │          │            │
     │          │            └─ 页内偏移 (0-4095)
     │          └────────────── 页表索引 (0-1023)
     └───────────────────────── 页目录索引 (0-1023)

转换过程：
1. CR3寄存器 → 页目录物理地址
2. 页目录索引 → 找到页表物理地址
3. 页表索引 → 找到物理页地址
4. 页内偏移 → 最终物理地址
```

#### C. 页目录表（Page Directory）

```
页目录：
- 大小：4KB（1024项 × 4字节）
- 每项指向一个页表
- 覆盖：每项管理4MB内存（1024页 × 4KB）
- 总覆盖：4GB（1024项 × 4MB）

页目录项（PDE）格式（32位）：
┌─┬─┬─┬─┬─┬─┬─┬─┬─┬────────────────────┐
│P│R│U│W│P│P│ │D│P│  物理页表地址[31:12] │
│ │/│/│T│C│W│0│ │S│  (4KB对齐，低12位为0) │
│ │W│S│ │D│T│ │ │ │                      │
└─┴─┴─┴─┴─┴─┴─┴─┴─┴────────────────────┘
31 9 8 7 6 5 4 3 2 1                    0

标志位说明：
P   (Present)       : 1=存在，0=不存在
R/W (Read/Write)    : 1=可写，0=只读
U/S (User/Supervisor): 1=用户，0=内核
PWT (Page Write-Through): 缓存策略
PCD (Page Cache Disable) : 禁用缓存
PS  (Page Size)     : 0=4KB页，1=4MB页
```

#### D. 页表（Page Table）

```
页表：
- 大小：4KB（1024项 × 4字节）
- 每项指向一个物理页
- 覆盖：4MB内存（1024页 × 4KB）

页表项（PTE）格式（32位）：
┌─┬─┬─┬─┬─┬─┬─┬─┬─┬────────────────────┐
│P│R│U│W│P│P│D│A│G│  物理页地址[31:12]   │
│ │/│/│T│C│W│ │ │ │  (4KB对齐)           │
│ │W│S│ │D│T│ │ │ │                      │
└─┴─┴─┴─┴─┴─┴─┴─┴─┴────────────────────┘
31 9 8 7 6 5 4 3 2 1                    0

额外标志：
D (Dirty)    : 1=已修改
A (Accessed) : 1=已访问
G (Global)   : 1=全局页（不刷新TLB）
```

### 3. 物理内存 vs 虚拟内存

| 特性 | 物理内存 | 虚拟内存 |
|------|---------|---------|
| 地址范围 | 0 到 物理内存大小 | 0 到 4GB (32位) |
| 访问方式 | 直接访问（禁用分页时） | 通过页表转换 |
| 碎片问题 | 外部碎片 | 内部碎片（页内） |
| 管理单位 | 页帧（Page Frame） | 页（Page） |
| 隔离性 | 无 | 完全隔离 |

## 🏗️ 内存布局设计

### 1. 物理内存布局

```
物理地址空间（示例：128MB）：
┌────────────────────────────┐ 0x08000000 (128MB)
│                            │
│      可用内存区域           │
│    (PMM管理的页帧)          │
│                            │
├────────────────────────────┤ 0x00400000 (4MB)
│    内核代码和数据           │
│    .text, .data, .bss      │
├────────────────────────────┤ 0x00100000 (1MB)
│    内核加载位置             │
├────────────────────────────┤ 0x000A0000 (640KB)
│    VGA显存                 │
├────────────────────────────┤ 0x00010000 (64KB)
│    BIOS数据区              │
├────────────────────────────┤ 0x00001000 (4KB)
│    BIOS中断向量表          │
└────────────────────────────┘ 0x00000000

保留区域：
- 0x00000000 - 0x00000FFF : BIOS中断向量表（不可用）
- 0x00001000 - 0x0009FFFF : 可用（低端内存）
- 0x000A0000 - 0x000FFFFF : VGA/BIOS（不可用）
- 0x00100000 - 内核结束   : 内核占用
- 内核结束 - 物理内存顶部 : 可用内存
```

### 2. 虚拟内存布局

```
虚拟地址空间（4GB）：
┌────────────────────────────┐ 0xFFFFFFFF (4GB)
│                            │
│      内核空间 (1GB)         │
│      DPL=0 (Ring 0)        │
│                            │
│  ┌──────────────────────┐  │
│  │  内核堆（动态分配）   │  │
│  ├──────────────────────┤  │
│  │  内核栈              │  │
│  ├──────────────────────┤  │
│  │  页表区域            │  │
│  ├──────────────────────┤  │
│  │  内核代码和数据       │  │
│  └──────────────────────┘  │
├────────────────────────────┤ 0xC0000000 (3GB)
│                            │
│      用户空间 (3GB)         │
│      DPL=3 (Ring 3)        │
│                            │
│  ┌──────────────────────┐  │
│  │  用户栈（向下增长）   │  │ 0xBFFFFFFF
│  │         ↓            │  │
│  │                      │  │
│  │                      │  │
│  │         ↑            │  │
│  │  用户堆（向上增长）   │  │
│  ├──────────────────────┤  │
│  │  .bss（未初始化）     │  │
│  ├──────────────────────┤  │
│  │  .data（已初始化）    │  │
│  ├──────────────────────┤  │
│  │  .text（代码段）      │  │
│  └──────────────────────┘  │ 0x08048000
│      保留区域              │
└────────────────────────────┘ 0x00000000

关键地址：
0xC0000000 : 内核空间起始（KERNEL_BASE）
0xC0100000 : 内核虚拟起始（1MB处映射）
0xC0400000 : 内核堆起始（假设内核4MB）
0xFFC00000 : 页目录递归映射位置
```

### 3. 高半核（Higher Half Kernel）

**为什么使用高半核？**

```
传统低地址内核（不好）：
┌────────────────┐ 4GB
│   用户空间     │ 3GB
├────────────────┤ 1GB
│   内核空间     │
└────────────────┘ 0

问题：
- 用户程序可能覆盖内核地址
- 难以保护内核

高半核（推荐）：
┌────────────────┐ 4GB
│   内核空间     │ 1GB
├────────────────┤ 3GB
│   用户空间     │
└────────────────┘ 0

优点：
- 内核固定在高地址
- 用户永远无法访问高地址
- 所有进程共享相同的内核映射
```

## 💻 代码实现详解

### 1. 物理内存管理器（PMM）

#### A. 位图算法

```c
// 每个位代表一个物理页帧（4KB）
// 0 = 空闲，1 = 占用
uint32_t *pmm_bitmap;
uint32_t pmm_total_frames;    // 总页帧数
uint32_t pmm_used_frames;     // 已用页帧数

// 示例：128MB内存
// 总页帧 = 128MB / 4KB = 32768 帧
// 位图大小 = 32768 / 8 = 4096 字节 = 1 页
```

#### B. 页帧分配

```c
// 分配一个物理页帧
uint32_t pmm_alloc_frame(void)
{
    // 扫描位图找到第一个空闲位
    for (uint32_t i = 0; i < pmm_total_frames; i++) {
        if (!pmm_test_frame(i)) {
            pmm_set_frame(i);
            pmm_used_frames++;
            return i * PAGE_SIZE;  // 返回物理地址
        }
    }
    return 0;  // 内存不足
}

// 释放一个物理页帧
void pmm_free_frame(uint32_t addr)
{
    uint32_t frame = addr / PAGE_SIZE;
    if (pmm_test_frame(frame)) {
        pmm_clear_frame(frame);
        pmm_used_frames--;
    }
}
```

### 2. 页表管理

#### A. 创建页表项

```c
// 创建页目录项（PDE）
uint32_t pde_create(uint32_t pt_phys, uint32_t flags)
{
    return (pt_phys & 0xFFFFF000) | (flags & 0xFFF);
}

// 创建页表项（PTE）
uint32_t pte_create(uint32_t page_phys, uint32_t flags)
{
    return (page_phys & 0xFFFFF000) | (flags & 0xFFF);
}

// 标志位
#define PAGE_PRESENT    0x001  // P: 页存在
#define PAGE_WRITE      0x002  // R/W: 可写
#define PAGE_USER       0x004  // U/S: 用户可访问
#define PAGE_PWT        0x008  // PWT: 写穿透
#define PAGE_PCD        0x010  // PCD: 禁用缓存
#define PAGE_ACCESSED   0x020  // A: 已访问
#define PAGE_DIRTY      0x040  // D: 已修改
#define PAGE_4MB        0x080  // PS: 4MB页
#define PAGE_GLOBAL     0x100  // G: 全局页
```

#### B. 地址映射

```c
// 映射虚拟地址到物理地址
void vmm_map_page(uint32_t virt, uint32_t phys, uint32_t flags)
{
    uint32_t pd_index = virt >> 22;              // 页目录索引
    uint32_t pt_index = (virt >> 12) & 0x3FF;    // 页表索引
    
    // 获取页目录
    uint32_t *page_directory = get_page_directory();
    
    // 检查页表是否存在
    if (!(page_directory[pd_index] & PAGE_PRESENT)) {
        // 分配新页表
        uint32_t pt_phys = pmm_alloc_frame();
        page_directory[pd_index] = pde_create(pt_phys, 
            PAGE_PRESENT | PAGE_WRITE | flags);
        
        // 清空页表
        uint32_t *page_table = (uint32_t*)(0xFFC00000 + pd_index * 0x1000);
        memset(page_table, 0, 4096);
    }
    
    // 获取页表并设置映射
    uint32_t *page_table = (uint32_t*)(0xFFC00000 + pd_index * 0x1000);
    page_table[pt_index] = pte_create(phys, PAGE_PRESENT | flags);
    
    // 刷新TLB
    invlpg(virt);
}
```

#### C. TLB刷新

```c
// 刷新单个页的TLB
static inline void invlpg(uint32_t addr)
{
    __asm__ volatile("invlpg (%0)" : : "r"(addr) : "memory");
}

// 刷新整个TLB（重新加载CR3）
static inline void flush_tlb(void)
{
    uint32_t cr3;
    __asm__ volatile("mov %%cr3, %0" : "=r"(cr3));
    __asm__ volatile("mov %0, %%cr3" : : "r"(cr3));
}
```

### 3. 动态内存分配器（kmalloc）

#### A. 简单首次适应算法

```c
struct heap_block {
    uint32_t size;              // 块大小（包括头）
    uint32_t magic;             // 魔数（用于检测）
    bool allocated;             // 是否已分配
    struct heap_block *next;    // 下一个块
};

void *kmalloc(size_t size)
{
    // 对齐到8字节
    size = ALIGN_UP(size, 8);
    
    // 搜索空闲块
    struct heap_block *block = heap_first;
    while (block) {
        if (!block->allocated && block->size >= size) {
            // 找到合适的块
            block->allocated = true;
            
            // 如果块太大，分割它
            if (block->size > size + sizeof(struct heap_block) + 32) {
                split_block(block, size);
            }
            
            return (void*)((uint32_t)block + sizeof(struct heap_block));
        }
        block = block->next;
    }
    
    // 没有找到，扩展堆
    return expand_heap(size);
}

void kfree(void *ptr)
{
    if (!ptr) return;
    
    struct heap_block *block = 
        (struct heap_block*)((uint32_t)ptr - sizeof(struct heap_block));
    
    // 验证魔数
    if (block->magic != HEAP_MAGIC) {
        panic("Invalid free: bad magic");
    }
    
    block->allocated = false;
    
    // 合并相邻空闲块
    merge_blocks(block);
}
```

## 🚨 缺页异常处理

### 1. 缺页异常触发条件

```c
// CPU在以下情况触发#PF（中断14）：
// 1. 页不存在（P=0）
// 2. 访问权限不足（U/S, R/W）
// 3. 访问保留位
```

### 2. 错误码分析

```c
void handle_page_fault(struct interrupt_frame *frame)
{
    // 读取CR2寄存器（引发异常的地址）
    uint32_t fault_addr;
    __asm__ volatile("mov %%cr2, %0" : "=r"(fault_addr));
    
    // 解析错误码
    uint32_t error_code = frame->err_code;
    bool present  = !(error_code & 0x1);  // 页不存在
    bool write    = error_code & 0x2;     // 写操作
    bool user     = error_code & 0x4;     // 用户模式
    bool reserved = error_code & 0x8;     // 保留位
    bool ifetch   = error_code & 0x10;    // 指令取指
    
    if (present) {
        // 页不存在 - 可能需要分配
        handle_demand_paging(fault_addr);
    } else if (!user) {
        // 内核权限错误 - 严重错误
        panic("Kernel page fault");
    } else {
        // 用户权限错误 - 终止进程
        kill_process(current_process);
    }
}
```

## 📊 内存管理算法对比

### 1. 物理内存管理算法

| 算法 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **位图** | 简单，O(n)查找 | 浪费空间 | 小型系统 |
| **空闲链表** | 灵活 | 碎片多 | 通用 |
| **伙伴系统** | 快速，减少碎片 | 内部碎片 | Linux |
| **Slab** | 对象重用，快速 | 复杂 | 对象缓存 |

### 2. 虚拟内存分配算法

| 算法 | 描述 | 性能 |
|------|------|------|
| **首次适应** | 找到第一个合适的块 | O(n) |
| **最佳适应** | 找最小的合适块 | O(n) |
| **最差适应** | 找最大的块 | O(n) |
| **快速适应** | 按大小分类 | O(1) |

## 🏗️ 第6部分：高半核架构（Higher-Half Kernel）

### 6.1 什么是高半核？

**问题**：在之前的实现中，内核被加载到物理地址1MB（0x100000），虚拟地址也是0x100000。这种**恒等映射**有什么问题？

**问题清单**：
1. **地址空间冲突**：用户程序也想使用低地址空间
2. **内核暴露**：用户可以直接访问内核内存
3. **不够灵活**：无法实现高级内存管理特性

**高半核解决方案**：

```
传统布局（恒等映射）:
虚拟地址 = 物理地址
┌─────────────────┐ 4GB
│     未使用      │
├─────────────────┤ 
│   用户程序      │
├─────────────────┤ 1MB
│   内核 ❌       │ <- 占用低地址
└─────────────────┘ 0

高半核布局（推荐）:
┌─────────────────┐ 4GB (0xFFFFFFFF)
│   内核 ✅       │ <- 虚拟地址在高地址
├─────────────────┤ 3GB (0xC0000000)
│                 │
│   用户空间      │ <- 3GB给用户使用
│                 │
└─────────────────┘ 0

物理内存仍然在1MB:
┌─────────────────┐
│   内核代码      │ <- 物理地址0x100000
└─────────────────┘
```

**映射关系**：
- 内核虚拟地址：0xC0000000 - 0xFFFFFFFF (3GB-4GB)
- 内核物理地址：0x00100000 - ... (1MB起)
- 偏移量：`KERNEL_OFFSET = 0xC0000000`

### 6.2 修改链接脚本

**文件**：`linker.ld`

```ld
/* 定义内核虚拟基址和物理基址 */
KERNEL_VIRTUAL_BASE = 0xC0000000;   /* 3GB */
KERNEL_PHYSICAL_BASE = 0x00100000;  /* 1MB */

SECTIONS
{
    /* 内核虚拟地址从3GB+1MB开始，物理地址在1MB */
    . = KERNEL_VIRTUAL_BASE + KERNEL_PHYSICAL_BASE;
    
    /* 保存内核起始地址 */
    kernel_virtual_start = .;
    kernel_physical_start = . - KERNEL_VIRTUAL_BASE;
    
    /* 代码段：AT()指定物理地址 */
    .text : AT(ADDR(.text) - KERNEL_VIRTUAL_BASE) ALIGN(4K)
    {
        *(.text)
        *(.text*)
    }
    
    /* 数据段 */
    .data : AT(ADDR(.data) - KERNEL_VIRTUAL_BASE) ALIGN(4K)
    {
        *(.data)
        *(.data*)
    }
    
    /* BSS段 */
    .bss : AT(ADDR(.bss) - KERNEL_VIRTUAL_BASE) ALIGN(4K)
    {
        *(COMMON)
        *(.bss)
        *(.bss*)
    }
    
    /* 保存内核结束地址 */
    kernel_virtual_end = .;
    kernel_physical_end = . - KERNEL_VIRTUAL_BASE;
    
    /* 兼容性符号 */
    kernel_end = kernel_physical_end;
}
```

**关键点**：
- `AT()` 指令指定段的**物理地址**
- 链接器按**虚拟地址**链接，加载器按**物理地址**加载
- 所有内核符号都是**虚拟地址**

### 6.3 Bootloader设置分页

**问题**：内核代码链接在虚拟地址0xC0100000，但物理内存在0x100000，如何跳转？

**答案**：在bootloader中设置分页，建立虚拟地址到物理地址的映射！

**文件**：`boot/stage2/loader_complete.asm`

```nasm
; 页表常量
PAGE_DIRECTORY_ADDR equ 0x9000      ; 页目录（36KB处）
PAGE_TABLE_0_ADDR   equ 0xA000      ; 页表0（40KB处）
PAGE_TABLE_768_ADDR equ 0xB000      ; 页表768（44KB处）

protected_mode_start:
    ; ... 前面的代码（设置段寄存器、复制内核等）...
    
    ; === 设置页表 ===
    
    ; 1. 清空页目录（1024个条目，每个4字节）
    mov edi, PAGE_DIRECTORY_ADDR
    mov ecx, 1024
    xor eax, eax
    rep stosd
    
    ; 2. 创建页表0：恒等映射0-4MB
    ;    用途：过渡期间访问低地址（bootloader代码、页表自身）
    mov edi, PAGE_TABLE_0_ADDR
    mov eax, 0x00000003         ; 物理地址0，Present + Writable
    mov ecx, 1024               ; 1024页 = 4MB
.fill_pt0:
    stosd
    add eax, 0x1000             ; 下一个4KB页
    loop .fill_pt0
    
    ; 3. 创建页表768：映射3GB-3GB+4MB到物理0-4MB
    ;    用途：内核运行在虚拟地址0xC0000000
    ;    计算：768 = 3GB / 4MB（每个页目录项映射4MB）
    mov edi, PAGE_TABLE_768_ADDR
    mov eax, 0x00000003         ; 物理地址0，Present + Writable
    mov ecx, 1024
.fill_pt768:
    stosd
    add eax, 0x1000
    loop .fill_pt768
    
    ; 4. 设置页目录条目
    mov eax, PAGE_TABLE_0_ADDR
    or eax, 0x00000003          ; Present + Writable
    mov [PAGE_DIRECTORY_ADDR], eax     ; PD[0] = 页表0
    
    mov eax, PAGE_TABLE_768_ADDR
    or eax, 0x00000003
    mov [PAGE_DIRECTORY_ADDR + 768*4], eax  ; PD[768] = 页表768
    
    ; 5. 加载页目录到CR3
    mov eax, PAGE_DIRECTORY_ADDR
    mov cr3, eax
    
    ; 6. 启用分页（设置CR0的PG位）
    mov eax, cr0
    or eax, 0x80000000          ; 位31 = PG
    mov cr0, eax
    
    ; 分页已启用！
    ; 现在跳转到内核的虚拟地址
    jmp 0x08:0xC0100000         ; 跳转到内核
```

**页表结构图**：

```
页目录（Page Directory）- 1024个条目
┌────┬─────────────────────────────┐
│  0 │ → 页表0 (0-4MB恒等映射)    │
├────┼─────────────────────────────┤
│  1 │ 空                          │
│ .. │ 空                          │
│767 │ 空                          │
├────┼─────────────────────────────┤
│768 │ → 页表768 (3GB-3GB+4MB)    │
├────┼─────────────────────────────┤
│769 │ 空                          │
│ .. │ 空                          │
│1023│ 空（后面会用作递归映射）    │
└────┴─────────────────────────────┘

页表0（恒等映射）:
┌────┬──────────┐
│  0 │ → 0x0000 │ 虚拟0x00000000 → 物理0x00000000
│  1 │ → 0x1000 │ 虚拟0x00001000 → 物理0x00001000
│ .. │   ...    │
│1023│ →0x3FF000│ 虚拟0x003FF000 → 物理0x003FF000
└────┴──────────┘

页表768（高半核映射）:
┌────┬──────────┐
│  0 │ → 0x0000 │ 虚拟0xC0000000 → 物理0x00000000
│  1 │ → 0x1000 │ 虚拟0xC0001000 → 物理0x00001000
│ .. │   ...    │
│1023│ →0x3FF000│ 虚拟0xC03FF000 → 物理0x003FF000
└────┴──────────┘
```

### 6.4 内核入口适配

**文件**：`kernel/arch/i386/entry.asm`

```nasm
[BITS 32]

extern kernel_main
global _start

section .text

_start:
    ; 现在我们已经在虚拟地址0xC0100000执行
    
    ; 设置段寄存器
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    
    ; 使用内核BSS段中的栈（虚拟地址）
    mov esp, kernel_stack_top
    mov ebp, esp
    
    ; 调用C内核
    call kernel_main
    
    ; 永远不应该到这里
halt:
    cli
    hlt
    jmp halt

section .bss
align 16
kernel_stack_bottom:
    resb 16384              ; 16KB内核栈
kernel_stack_top:
```

### 6.5 VMM继承Bootloader页表

**文件**：`kernel/mm/vmm.c`

```c
void vmm_init(uint32_t kernel_end_phys)
{
    kprintf("[VMM] Initializing Virtual Memory Manager...\n");
    
    /* 从CR3获取bootloader创建的页目录地址 */
    uint32_t pd_phys = vmm_get_cr3();  // 应该是0x9000
    kprintf("[VMM] Inherited Page Directory: 0x%08x\n", pd_phys);
    
    kernel_directory.physical_addr = pd_phys;
    
    /* 由于已经启用分页，通过恒等映射访问页目录 */
    uint32_t *pd = (uint32_t*)pd_phys;
    
    /* 设置递归映射：PD[1023]指向页目录自己 */
    pd[1023] = pde_create(pd_phys, PAGE_PRESENT | PAGE_WRITE);
    
    /* 刷新TLB */
    vmm_set_cr3(pd_phys);
    
    /* 现在可以通过0xFFFFF000访问页目录 */
    kernel_directory.entries = GET_PAGE_DIRECTORY();
    current_directory = &kernel_directory;
    
    kprintf("[VMM] Address space layout:\n");
    kprintf("      Identity: 0x00000000 - 0x003FFFFF\n");
    kprintf("      Kernel:   0xC0000000 - 0xC03FFFFF\n");
    kprintf("[VMM] VMM initialized\n\n");
}
```

### 6.6 优势和权衡

**优势**：
1. ✅ **用户空间更大**：3GB给用户程序使用
2. ✅ **内核隔离**：用户程序无法直接访问内核
3. ✅ **统一地址空间**：所有进程共享相同的内核映射
4. ✅ **简化上下文切换**：切换进程时不需要切换内核映射

**权衡**：
1. ⚠️ **复杂性增加**：需要在bootloader中设置分页
2. ⚠️ **地址转换**：访问物理内存需要减去偏移量
3. ⚠️ **调试困难**：虚拟地址和物理地址不同

### 6.7 常见陷阱

**陷阱1：物理地址和虚拟地址混淆**

```c
// ❌ 错误：kernel_end是虚拟地址
extern uint32_t kernel_end;
pmm_init(mem_size, 0x100000, kernel_end);

// ✅ 正确：减去偏移得到物理地址
extern uint32_t kernel_end;
uint32_t kernel_end_phys = (uint32_t)&kernel_end - 0xC0000000;
pmm_init(mem_size, 0x100000, kernel_end_phys);
```

**陷阱2：忘记恒等映射**

```nasm
; ❌ 错误：启用分页后立即跳转到高地址
mov cr0, eax            ; 启用分页
jmp 0x08:0xC0100000     ; 崩溃！下一条指令的地址还是低地址

; ✅ 正确：使用恒等映射作为过渡
mov cr0, eax            ; 启用分页
; 此时还在低地址执行（通过恒等映射）
jmp 0x08:0xC0100000     ; 现在才跳转到高地址
```

**陷阱3：访问页表本身**

```c
// ❌ 错误：页目录在物理地址0x9000，分页后无法直接访问
uint32_t *pd = (uint32_t*)0x9000;  // 这是虚拟地址！

// ✅ 正确方法1：通过恒等映射访问（低4MB）
uint32_t *pd = (uint32_t*)0x9000;  // OK，因为0x9000 < 4MB

// ✅ 正确方法2：使用递归映射
uint32_t *pd = GET_PAGE_DIRECTORY();  // 0xFFFFF000
```

### 6.8 调试技巧

**查看当前地址空间**：

```c
void debug_print_cr3(void)
{
    uint32_t cr3;
    asm volatile("mov %%cr3, %0" : "=r"(cr3));
    kprintf("CR3 (Page Directory): 0x%08x\n", cr3);
}

void debug_print_address(void *ptr)
{
    uint32_t virt = (uint32_t)ptr;
    uint32_t pd_idx = virt >> 22;
    uint32_t pt_idx = (virt >> 12) & 0x3FF;
    uint32_t offset = virt & 0xFFF;
    
    kprintf("Virtual: 0x%08x\n", virt);
    kprintf("  PD[%u] PT[%u] Offset:%u\n", pd_idx, pt_idx, offset);
}
```

## 📊 性能考虑

### 内存分配器性能

**首次适配算法（当前实现）**：
- 分配时间：O(n)，n=块数
- 释放时间：O(n)
- 碎片化：中等

**优化方向**：
1. **分离空闲链表**：按大小分类
   - 16B, 32B, 64B, ..., 4KB
   - 分配时间：O(1)
   
2. **伙伴系统**（Buddy System）
   - 2的幂次大小
   - 快速合并
   
3. **Slab分配器**
   - 对象缓存
   - 减少碎片

### TLB优化

**TLB（Translation Lookaside Buffer）**：页表缓存

```c
/* 刷新单个TLB条目 */
static inline void invlpg(uint32_t virt_addr)
{
    asm volatile("invlpg (%0)" : : "r"(virt_addr) : "memory");
}

/* 只刷新必要的条目，不要全部刷新 */
void vmm_map_page(uint32_t virt, uint32_t phys, uint32_t flags)
{
    // ... 设置页表 ...
    invlpg(virt);  // ✅ 只刷新这一页
    // 不要用：vmm_set_cr3(cr3);  // ❌ 刷新全部TLB
}
```
