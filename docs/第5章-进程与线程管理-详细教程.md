## 🎯 核心概念

### 1. 什么是进程？

**定义**：进程是**正在执行的程序**的实例，是操作系统进行资源分配和调度的基本单位。

**程序 vs 进程**：

```
程序（Program）：
- 静态的代码文件（存储在磁盘上）
- 例如：/bin/ls

进程（Process）：
- 正在运行的程序实例
- 包含：代码 + 数据 + 栈 + 堆 + CPU状态
- 例如：正在执行的ls命令
```

**进程的组成部分**：

```
进程 = 代码 + 数据 + 状态

┌─────────────────────────────────┐
│  进程控制块 (PCB)               │
│  - PID, 状态, 优先级            │
│  - CPU寄存器（上下文）          │
│  - 内存映射                     │
├─────────────────────────────────┤
│  代码段 (.text)                 │
│  - 机器指令                     │
├─────────────────────────────────┤
│  数据段 (.data, .bss)           │
│  - 全局变量、静态变量           │
├─────────────────────────────────┤
│  堆 (Heap) ↓                    │
│  - 动态分配的内存               │
│                                 │
│                                 │
│  栈 (Stack) ↑                   │
│  - 函数调用、局部变量           │
└─────────────────────────────────┘
```

### 2. 进程状态

**五状态模型**：

```
       ┌─────────┐
       │  NEW    │ 创建
       │ （新建） │
       └────┬────┘
            │ admit
            ↓
       ┌─────────┐
  ┌───→│ READY   │←────┐
  │    │（就绪）  │     │ timeout
  │    └────┬────┘     │
  │         │ dispatch │
  │         ↓          │
  │    ┌─────────┐     │
  │    │RUNNING  │─────┘
  │    │（运行）  │
  │    └────┬────┘
  │         │ I/O or event wait
  │         ↓
  │    ┌─────────┐
  └────│BLOCKED  │
       │（阻塞）  │
       └────┬────┘
            │ exit
            ↓
       ┌─────────┐
       │TERMINATED│
       │ （终止） │
       └─────────┘
```

**状态说明**：
- **NEW**：进程正在被创建
- **READY**：进程已就绪，等待CPU
- **RUNNING**：进程正在CPU上执行
- **BLOCKED**：进程等待I/O或事件
- **TERMINATED**：进程已结束

### 3. 进程切换（Context Switch）

**什么时候切换？**
1. 时间片用完（timer interrupt）
2. 进程阻塞（等待I/O）
3. 进程主动让出CPU（yield）
4. 更高优先级进程就绪

**切换过程**：

```
进程A运行中 → 中断发生 → 保存进程A状态 → 选择进程B → 恢复进程B状态 → 进程B运行

详细步骤：
1. 定时器中断（IRQ0）触发
2. CPU自动保存：
   - EIP（指令指针）
   - CS（代码段）
   - EFLAGS（标志寄存器）
   - ESP（栈指针）
   - SS（栈段）
   
3. 中断处理程序保存其余寄存器：
   - EAX, EBX, ECX, EDX
   - ESI, EDI, EBP
   - DS, ES, FS, GS
   
4. 调度器选择下一个进程
5. 恢复新进程的寄存器
6. 返回新进程执行（iret）
```

### 4. 进程调度算法

**先来先服务（FCFS）**：
```
进程队列: [P1] → [P2] → [P3]
按到达顺序执行
优点：简单
缺点：平均等待时间长
```

**时间片轮转（Round Robin）** ⭐ 我们将实现这个：
```
时间片 = 10ms

时间: 0     10    20    30    40
进程: P1 → P2 → P3 → P1 → P2 ...

优点：公平，响应快
缺点：上下文切换开销
```

**优先级调度**：
```
高优先级: [P1] → [P2]
低优先级: [P3] → [P4]

优点：重要任务优先
缺点：可能饿死低优先级进程
```

### 5. 内核线程 vs 用户进程

**内核线程（Kernel Thread）**：
```
- 运行在内核空间（Ring 0）
- 可以直接访问硬件
- 共享内核地址空间
- 轻量级，创建快
- 例如：idle进程、工作线程
```

**用户进程（User Process）**：
```
- 运行在用户空间（Ring 3）
- 通过系统调用访问内核
- 独立的地址空间
- 隔离性好，安全
- 例如：应用程序
```

## 🏗️ 第1部分：进程控制块（PCB）设计

### 1.1 PCB是什么？

**PCB（Process Control Block）**：操作系统用来描述和管理进程的数据结构。

**类比**：PCB就像人的"档案"，包含了所有必要信息：
- 身份证号（PID）
- 姓名（进程名）
- 状态（就绪/运行/阻塞）
- 当前位置（CPU寄存器）
- 家庭住址（内存地址空间）

### 1.2 PCB包含哪些信息？

```c
/* 进程状态 */
typedef enum {
    PROCESS_STATE_NEW = 0,       /* 新建 */
    PROCESS_STATE_READY,         /* 就绪 */
    PROCESS_STATE_RUNNING,       /* 运行 */
    PROCESS_STATE_BLOCKED,       /* 阻塞 */
    PROCESS_STATE_TERMINATED     /* 终止 */
} process_state_t;

/* CPU上下文（进程切换时保存的寄存器） */
struct cpu_context {
    uint32_t eax;
    uint32_t ebx;
    uint32_t ecx;
    uint32_t edx;
    uint32_t esi;
    uint32_t edi;
    uint32_t ebp;
    uint32_t esp;        /* 栈指针 */
    uint32_t eip;        /* 指令指针 */
    uint32_t eflags;     /* 标志寄存器 */
    uint32_t cr3;        /* 页目录基址 */
};

/* 进程控制块 */
struct process {
    /* 基本信息 */
    uint32_t pid;                /* 进程ID */
    char name[32];               /* 进程名 */
    process_state_t state;       /* 进程状态 */
    uint32_t priority;           /* 优先级（0-31） */
    
    /* CPU上下文 */
    struct cpu_context context;  /* 保存的寄存器 */
    
    /* 内存管理 */
    struct page_directory *page_dir;  /* 页目录 */
    uint32_t kernel_stack;       /* 内核栈地址 */
    uint32_t user_stack;         /* 用户栈地址（用户进程） */
    
    /* 调度信息 */
    uint32_t time_slice;         /* 时间片（tick数） */
    uint32_t time_used;          /* 已使用时间 */
    uint64_t total_runtime;      /* 总运行时间（统计） */
    
    /* 链表节点 */
    struct process *next;        /* 下一个进程 */
    struct process *prev;        /* 上一个进程 */
    
    /* 父子关系 */
    struct process *parent;      /* 父进程 */
    struct process *first_child; /* 第一个子进程 */
    struct process *next_sibling;/* 下一个兄弟进程 */
    
    /* 其他信息 */
    uint32_t exit_code;          /* 退出码 */
    uint64_t start_time;         /* 启动时间 */
};
```

**字段详解**：

1. **pid**：进程唯一标识符
   ```c
   pid = 0: idle进程（空闲时运行）
   pid = 1: init进程（第一个用户进程）
   pid ≥ 2: 其他进程
   ```

2. **state**：当前状态
   ```
   NEW → READY → RUNNING → BLOCKED → READY → ... → TERMINATED
   ```

3. **context**：CPU状态快照
   ```
   进程A运行时：
   EIP = 0xC0101234  （正在执行的指令地址）
   ESP = 0xC0200FF0  （栈顶）
   EAX = 123         （寄存器值）
   ...
   
   切换到进程B后，需要恢复进程A的这些值才能继续运行
   ```

4. **page_dir**：进程的虚拟地址空间
   ```
   每个进程有独立的页目录 → 独立的地址空间 → 进程隔离
   ```

5. **kernel_stack**：内核栈
   ```
   进程陷入内核时（系统调用、中断）使用
   每个进程都有独立的内核栈
   ```

## 🏗️ 第2部分：进程调度器

### 2.1 调度器的职责

**调度器（Scheduler）**负责：
1. 维护就绪队列（ready queue）
2. 选择下一个运行的进程
3. 触发上下文切换
4. 管理时间片

**数据结构**：

```c
/* 调度器 */
struct scheduler {
    struct process *current;      /* 当前运行的进程 */
    struct process *idle_process; /* idle进程（CPU空闲时运行） */
    struct process *ready_queue_head;  /* 就绪队列头 */
    struct process *ready_queue_tail;  /* 就绪队列尾 */
    uint32_t process_count;       /* 进程总数 */
    uint32_t ready_count;         /* 就绪进程数 */
    uint32_t running_count;       /* 运行进程数（应该≤CPU核心数） */
    uint64_t total_switches;      /* 总切换次数 */
};
```

**就绪队列**：

```
FIFO队列（先进先出）:

Head → [P3] → [P1] → [P5] → NULL
       (next) (next) (next)

调度：
1. 从Head取出P3
2. P3运行一个时间片
3. P3放回Tail（如果还要继续运行）
```

### 2.3 调度算法实现

**时间片轮转（Round Robin）**：

```c
struct process *scheduler_pick_next(void)
{
    /* 如果就绪队列为空，返回idle进程 */
    if (ready_queue_head == NULL) {
        return idle_process;
    }
    
    /* 从队列头取出一个进程 */
    struct process *next = ready_queue_head;
    
    /* 从队列中移除 */
    ready_queue_head = next->next;
    if (ready_queue_head == NULL) {
        ready_queue_tail = NULL;
    } else {
        ready_queue_head->prev = NULL;
    }
    next->next = next->prev = NULL;
    
    ready_count--;
    
    return next;
}

void scheduler_schedule(void)
{
    struct process *current = scheduler_current;
    struct process *next = scheduler_pick_next();
    
    if (next == NULL) {
        return;  /* 没有可运行的进程 */
    }
    
    /* 如果当前进程还在运行且时间片未用完，不切换 */
    if (current && current->state == PROCESS_STATE_RUNNING
        && current->time_used < current->time_slice) {
        /* 把next放回就绪队列 */
        scheduler_add_process(next);
        return;
    }
    
    /* 需要切换 */
    if (current && current->state == PROCESS_STATE_RUNNING) {
        /* 当前进程变为就绪状态 */
        current->state = PROCESS_STATE_READY;
        current->time_used = 0;  /* 重置时间片 */
        scheduler_add_process(current);  /* 放回就绪队列尾部 */
    }
    
    /* 新进程开始运行 */
    next->state = PROCESS_STATE_RUNNING;
    next->time_used = 0;
    scheduler_current = next;
    
    /* 执行上下文切换 */
    if (current != next) {
        context_switch(current, next);
    }
}
```

## 🏗️ 第3部分：上下文切换

### 3.1 什么是上下文切换？

**Context Switch**：保存当前进程的CPU状态，加载新进程的CPU状态。

**为什么需要？**
```
进程A正在执行：
  EIP = 0xC0101234
  ESP = 0xC0200FF0
  EAX = 42

时间片用完，切换到进程B：
  EIP = 0xC0105678
  ESP = 0xC0300AB0
  EAX = 100

将来再切换回进程A时，必须恢复EIP, ESP, EAX等值，
才能从之前的位置继续执行！
```

### 3.2 上下文切换流程

```
1. 保存当前进程的寄存器到PCB
   ┌──────────────────────┐
   │ 进程A的PCB           │
   │ context.eax = 42     │
   │ context.ebx = 123    │
   │ context.esp = ...    │
   │ context.eip = ...    │
   └──────────────────────┘

2. 切换页目录（如果地址空间不同）
   mov cr3, [next_process->page_dir]

3. 切换内核栈
   mov esp, [next_process->kernel_stack]

4. 恢复新进程的寄存器
   ┌──────────────────────┐
   │ 进程B的PCB           │
   │ context.eax → EAX    │
   │ context.ebx → EBX    │
   │ context.esp → ESP    │
   │ context.eip → EIP    │
   └──────────────────────┘

5. 返回到新进程执行
```

### 3.3 汇编实现

**文件**：`kernel/process/context_switch.asm`

```nasm
; ===========================================================================
; context_switch.asm - 进程上下文切换
; ===========================================================================
; 原型：void context_switch(struct process *prev, struct process *next)
; ===========================================================================

[BITS 32]

global context_switch
extern scheduler_current

section .text

; ---------------------------------------------------------------------------
; context_switch - 执行上下文切换
; 参数：
;   [ebp+8]  = prev (旧进程)
;   [ebp+12] = next (新进程)
; ---------------------------------------------------------------------------
context_switch:
    push ebp
    mov ebp, esp
    
    mov eax, [ebp+8]     ; eax = prev
    mov ebx, [ebp+12]    ; ebx = next
    
    ; 如果prev为NULL（初次调度），跳过保存
    test eax, eax
    jz .load_next
    
    ; === 保存旧进程状态 ===
    ; struct process {
    ;     ...
    ;     struct cpu_context context;  // 偏移量需要根据实际结构计算
    ;     ...
    ; }
    ; 假设context在偏移32处（pid=0, name=32, ...）
    
    lea ecx, [eax+40]    ; ecx = &prev->context (假设偏移40)
    
    ; 保存通用寄存器
    mov [ecx+0],  edi
    mov [ecx+4],  esi
    mov [ecx+8],  ebp
    mov [ecx+12], esp
    mov [ecx+16], ebx
    mov [ecx+20], edx
    mov [ecx+24], ecx
    ; eax已经在栈上，稍后保存
    
    ; 保存返回地址（EIP）
    mov edx, [ebp+4]     ; 返回地址
    mov [ecx+32], edx    ; context.eip
    
    ; 保存EFLAGS
    pushfd
    pop edx
    mov [ecx+40], edx    ; context.eflags
    
.load_next:
    ; === 加载新进程状态 ===
    lea ecx, [ebx+40]    ; ecx = &next->context
    
    ; 切换页目录（如果不同）
    mov edx, [ebx+48]    ; next->page_dir（假设偏移48）
    test edx, edx
    jz .skip_cr3
    
    ; 获取物理地址并加载到CR3
    mov edx, [edx]       ; page_dir->physical_addr
    mov cr3, edx
    
.skip_cr3:
    ; 切换内核栈
    mov esp, [ecx+12]    ; context.esp
    
    ; 恢复通用寄存器
    mov edi, [ecx+0]
    mov esi, [ecx+4]
    mov ebp, [ecx+8]
    mov ebx, [ecx+16]
    mov edx, [ecx+20]
    ; ecx和eax最后恢复
    
    ; 恢复EFLAGS
    mov eax, [ecx+40]
    push eax
    popfd
    
    ; 准备返回地址
    mov eax, [ecx+32]    ; context.eip
    mov [esp], eax       ; 修改栈上的返回地址
    
    ; 恢复eax和ecx
    mov eax, [ecx+28]
    mov ecx, [ecx+24]
    
    ; 更新当前进程指针
    mov [scheduler_current], ebx
    
    ; 返回到新进程
    ret
```

**关键点**：
1. **保存所有寄存器**：包括通用寄存器、EIP、EFLAGS、ESP
2. **切换页目录**：`mov cr3, [new_cr3]`，如果地址空间不同
3. **切换栈**：`mov esp, [new_esp]`
4. **恢复所有寄存器**：从新进程的PCB恢复
5. **返回**：`ret`会跳转到新进程的EIP

### 3.4 C语言接口

**文件**：`kernel/process/context_switch.c`

```c
#include <process/process.h>
#include <process/scheduler.h>

/* 汇编实现的上下文切换 */
extern void context_switch_asm(struct process *prev, struct process *next);

void context_switch(struct process *prev, struct process *next)
{
    if (next == NULL) {
        panic("context_switch: next is NULL");
    }
    
    /* 统计 */
    if (prev) {
        prev->total_runtime += prev->time_used;
    }
    
    /* 执行汇编级别的切换 */
    context_switch_asm(prev, next);
    
    /* 注意：这里的代码会在切换回来后执行 */
}
```

## 🏗️ 第4部分：进程创建

### 4.1 创建内核线程

**步骤**：
1. 分配PCB
2. 分配内核栈
3. 设置初始上下文
4. 加入就绪队列

**代码**：

```c
struct process *process_create_kernel_thread(
    const char *name,
    void (*entry)(void),
    uint32_t priority)
{
    /* 1. 分配PCB */
    struct process *proc = (struct process*)kmalloc(sizeof(struct process));
    if (!proc) {
        return NULL;
    }
    
    memset(proc, 0, sizeof(struct process));
    
    /* 2. 设置基本信息 */
    proc->pid = process_allocate_pid();
    strncpy(proc->name, name, 31);
    proc->name[31] = '\0';
    proc->state = PROCESS_STATE_NEW;
    proc->priority = priority;
    proc->time_slice = 10;  /* 10 ticks */
    proc->start_time = timer_get_ticks();
    
    /* 3. 分配内核栈（4KB） */
    proc->kernel_stack = (uint32_t)kmalloc(4096);
    if (!proc->kernel_stack) {
        kfree(proc);
        return NULL;
    }
    
    /* 4. 设置初始栈帧 */
    /*
       栈布局（从高地址到低地址）：
       +------------------+
       | eflags           | <- 初始EFLAGS
       | cs               | <- 内核代码段
       | eip              | <- entry函数地址
       | error_code       | <- 0（占位）
       | eax,ecx,edx,...  | <- 通用寄存器（初始化为0）
       +------------------+
    */
    
    uint32_t *stack_top = (uint32_t*)(proc->kernel_stack + 4096);
    
    /* 模拟中断栈帧 */
    *(--stack_top) = 0x00000202;  /* EFLAGS: IF=1（允许中断） */
    *(--stack_top) = 0x08;         /* CS: 内核代码段 */
    *(--stack_top) = (uint32_t)entry;  /* EIP: 入口函数 */
    *(--stack_top) = 0;            /* error_code（占位） */
    
    /* 通用寄存器（初始化为0） */
    *(--stack_top) = 0;  /* EAX */
    *(--stack_top) = 0;  /* ECX */
    *(--stack_top) = 0;  /* EDX */
    *(--stack_top) = 0;  /* EBX */
    *(--stack_top) = 0;  /* ESP（占位） */
    *(--stack_top) = 0;  /* EBP */
    *(--stack_top) = 0;  /* ESI */
    *(--stack_top) = 0;  /* EDI */
    
    /* 5. 设置context */
    proc->context.esp = (uint32_t)stack_top;
    proc->context.eip = (uint32_t)entry;
    proc->context.eflags = 0x202;  /* IF=1 */
    
    /* 6. 内核线程使用内核页目录 */
    proc->page_dir = NULL;  /* NULL表示使用内核页目录 */
    
    /* 7. 添加到调度器 */
    proc->state = PROCESS_STATE_READY;
    scheduler_add_process(proc);
    
    kprintf("[PROCESS] Created kernel thread: %s (PID %u)\n",
            proc->name, proc->pid);
    
    return proc;
}
```

### 4.2 入口函数包装

**问题**：如果线程函数返回了怎么办？

**解决**：提供一个包装函数，捕获返回并清理进程：

```c
/* 内核线程入口包装器 */
static void kernel_thread_wrapper(void (*fn)(void))
{
    /* 启用中断（进程初次运行时中断是关闭的） */
    sti();
    
    /* 调用用户提供的函数 */
    fn();
    
    /* 如果函数返回，退出进程 */
    process_exit(0);
}

/* 创建时设置入口为包装器 */
proc->context.eip = (uint32_t)kernel_thread_wrapper;
/* 把实际函数地址作为参数传递（通过栈或寄存器） */
```

### 5.1 定时器中断处理

**修改**：`kernel/drivers/timer.c`

```c
void timer_handler(struct interrupt_frame *frame)
{
    timer_ticks++;
    
    /* 每个tick，当前进程的时间片减少 */
    struct process *current = scheduler_get_current();
    if (current) {
        current->time_used++;
        
        /* 时间片用完，触发调度 */
        if (current->time_used >= current->time_slice) {
            scheduler_schedule();
        }
    }
    
    /* 每秒打印一次 */
    if (timer_ticks % 100 == 0) {
        kprintf("[TIMER] Tick %llu\n", timer_ticks);
    }
    
    pic_send_eoi(IRQ_TIMER);
}
```
