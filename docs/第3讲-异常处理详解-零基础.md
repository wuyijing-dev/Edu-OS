## 📖 第一课：什么是异常

### 1.1 从错误说起

**在普通程序中：**

```c
int main() {
    int x = 10;
    int y = 0;
    int z = x / y;  // 除以零！
    
    // 程序崩溃...
}
```

**在 Windows 中看到：**

```
╔════════════════════════════════╗
║ 程序 xxx.exe 遇到问题需要关闭      ║
║                                ║
║ [发送错误报告]  [不发送]          ║
╚════════════════════════════════╝
```

**在操作系统内核中：**
```
没有 Windows 来捕获错误！
除以零会发生什么？

答案：CPU 触发异常！
  → 查 IDT 中断 0
  → 跳转到异常处理程序
  → 你的代码决定怎么办
```

---

### 1.2 异常 vs 中断

**核心区别：**

| 特性 | 中断（Interrupt） | 异常（Exception） |
|------|------------------|-------------------|
| 来源 | 外部硬件 | CPU 内部 |
| 时机 | 异步（随时） | 同步（执行指令时） |
| 可预测 | 不可预测 | 可预测 |
| 可屏蔽 | 部分可以 | 不可以 |
| 示例 | 键盘、定时器 | 除零、缺页 |

**异步 vs 同步：**

```
中断（异步）：
  CPU 正在执行代码...
  突然！定时器中断  ← 不知道什么时候发生
  
异常（同步）：
  CPU 执行 DIV 指令
  → 发现除数是 0
  → 立即触发异常  ← 总是在这条指令
```

**类比：**
```
中断 = 门铃响了
  → 不知道什么时候会响
  → 正在做任何事情都可能被打断
  
异常 = 走路摔倒了
  → 明确是在"走路"这个动作时
  → 可重现（再走一次还会摔）
```

### 1.3 x86 的 32 个异常

**异常编号 0-31（CPU 保留）：**

| 编号 | 名称 | 符号 | 说明 |
|------|------|------|------|
| 0 | Divide Error | #DE | 除零或除法溢出 |
| 1 | Debug | #DB | 调试异常 |
| 2 | NMI | - | 不可屏蔽中断 |
| 3 | Breakpoint | #BP | INT 3 指令 |
| 4 | Overflow | #OF | INTO 指令 |
| 5 | Bound Range | #BR | BOUND 指令 |
| 6 | Invalid Opcode | #UD | 无效指令 |
| 7 | Device Not Available | #NM | FPU 不可用 |
| 8 | Double Fault | #DF | 双重故障 |
| 9 | - | - | 协处理器段越界 |
| 10 | Invalid TSS | #TS | 无效 TSS |
| 11 | Segment Not Present | #NP | 段不存在 |
| 12 | Stack Fault | #SS | 栈段故障 |
| 13 | General Protection | #GP | 保护故障 |
| 14 | Page Fault | #PF | 缺页异常 |
| 15 | - | - | Intel 保留 |

| 20-31 | - | - | Intel 保留 |

**最常见的 5 个异常：**
1. #DE (0)  - 除零
2. #UD (6)  - 无效指令
3. #GP (13) - 保护故障（最常见！）
4. #PF (14) - 缺页异常
5. #DF (8)  - 双重故障（最危险！）

## 📖 第二课：异常详解

### 2.1 除零异常 (#DE, 0)

**触发条件：**

```c
int x = 10;
int y = 0;
int z = x / y;  ← 触发异常 0
```

**或者：**
```asm
mov eax, 10
mov ebx, 0
div ebx         ; 触发异常 0
```

**异常处理：**

```c
void divide_error_handler(void)
{
    kprintf("╔════════════════════════════════╗\n");
    kprintf("║ EXCEPTION: Divide by Zero (#DE)║\n");
    kprintf("║                                ║\n");
    kprintf("║ 程序尝试除以零！              ║\n");
    kprintf("╚════════════════════════════════╝\n");
    
    // 选项1：终止当前进程
    process_kill_current();
    
    // 选项2：忽略（危险！）
    // 选项3：系统崩溃
    panic("Divide by zero");
}
```

### 2.2 保护故障 (#GP, 13)

**#GP = General Protection Fault**

**这是最常见的异常！各种错误都可能触发：**

**原因1：访问不存在的内存**
```c
int *ptr = (int*)0x0;  // 空指针
int value = *ptr;       // 触发 #GP (如果没启用分页)
```

**原因2：特权级违规**
```c
// 用户态程序（Ring 3）
asm("cli");  // CLI 是特权指令
             // 触发 #GP！
```

**原因3：段错误**
```asm
mov ax, 0x1234  ; 无效的段选择子
mov ds, ax      ; 触发 #GP
```

**原因4：访问超出段限制**
```
段限制 = 0xFFFF (64KB)
访问偏移 = 0x10000 (64KB+1)
  → 触发 #GP
```

**异常处理：**

```c
void general_protection_handler(struct interrupt_frame *frame)
{
    kprintf("╔════════════════════════════════╗\n");
    kprintf("║ EXCEPTION: General Protection  ║\n");
    kprintf("╚════════════════════════════════╝\n");
    
    kprintf("错误码: 0x%X\n", frame->error_code);
    kprintf("CS:EIP = 0x%04X:0x%08X\n", frame->cs, frame->eip);
    kprintf("EFLAGS = 0x%08X\n", frame->eflags);
    
    // 打印栈回溯
    print_stack_trace();
    
    // 终止进程或系统
    panic("General Protection Fault");
}
```

**错误码的含义：**

```
错误码（16位）：

Bit 0:   EXT  - 外部事件
Bit 1:   IDT  - IDT中的描述符
Bit 2:   TI   - GDT(0) 还是 LDT(1)
Bit 3-15: Index - 段选择子索引

示例：
  错误码 = 0x0002
  → Bit 1 = 1 → IDT 中的描述符
  → Index = 0 → IDT[0]
  → 说明是中断 0 的描述符有问题
```

### 2.3 缺页异常 (#PF, 14)

**#PF = Page Fault**

**这是内存管理的核心！**

**触发时机：**
```
启用分页后：
  所有内存访问都通过页表
  
  如果访问的虚拟地址没有映射：
    → 触发缺页异常
```

**示例：**
```c
// 假设 0x80000000 没有映射
int *ptr = (int*)0x80000000;
int value = *ptr;  // 触发 #PF
```

**CR2 寄存器：**

```
CR2 = 触发缺页的虚拟地址

在处理程序中：
  asm("mov %%cr2, %0" : "=r"(fault_addr));
  kprintf("Page fault at: 0x%08X\n", fault_addr);
```

**错误码（特殊）：**

```
Bit 0: P  - Present (0=页不存在, 1=保护违规)
Bit 1: W/R - Write/Read (0=读, 1=写)
Bit 2: U/S - User/Supervisor (0=内核态, 1=用户态)
Bit 3: RSVD - 保留位错误
Bit 4: I/D - Instruction/Data (0=数据, 1=取指令)

示例：
  错误码 = 0x02 = 0000 0010
  → P=0（页不存在）
  → W/R=1（尝试写入）
  
  说明：程序尝试写入一个未映射的页
```

**缺页处理（EduOS实际实现）：**

基于 `kernel/arch/i386/exception.c` 和 `kernel/mm/vma.c`:

```c
static int handle_page_fault(struct interrupt_frame *frame)
{
    /* 读取CR2寄存器（引发缺页的地址） */
    uint32_t fault_addr;
    __asm__ volatile("mov %%cr2, %0" : "=r"(fault_addr));
    
    /* 解析错误码 */
    bool present  = frame->err_code & 0x1;   // 页存在？
    bool write    = frame->err_code & 0x2;   // 写操作？
    bool user     = frame->err_code & 0x4;   // 用户模式？
    bool reserved = frame->err_code & 0x8;   // 保留位？
    bool ifetch   = frame->err_code & 0x10;  // 取指令？
    
    /* 内核空间缺页 → panic */
    if (!user) {
        panic("Kernel page fault");
        return -1;
    }
    
    /* 用户空间缺页 - Linux风格按需分配 */
    struct process *proc = process_get_current();
    
    if (proc) {
        /* 检查Copy-On-Write（页存在但写保护） */
        if (present && write) {
            // COW处理...
            return 0;  /* 成功处理 */
        }
        
        /* 检查VMA（虚拟内存区域） */
        if (proc->vma_list && !present) {
            struct vma *vma = vma_find(proc->vma_list, fault_addr);
            if (vma) {
                /* 尝试按需分配 */
                if (vma_handle_page_fault(vma, fault_addr, 
                                         proc->page_dir) == 0) {
                    return 0;  /* 成功处理，静默返回 */
                }
            }
        }
    }
    
    /* 无法处理 → 终止进程 */
    kprintf("\n[PAGE FAULT] Unhandled user space fault\n");
    kprintf("  Address: 0x%08x\n", fault_addr);
    kprintf("  Process: %s (PID %u)\n", 
            proc ? proc->name : "unknown", 
            proc ? proc->pid : 0);
    kprintf("  Cause: %s %s\n",
            write ? "Write" : ifetch ? "Instruction fetch" : "Read",
            present ? "protection violation" : "non-present page");
    
    if (proc) {
        proc->state = PROCESS_STATE_TERMINATED;
        proc->exit_code = -11;  /* SIGSEGV */
        scheduler_schedule();  // 切换到其他进程
    }
    
    return -1;
}
```

**EduOS的Page Fault处理分三种情况：**

1. **页不存在** → VMA按需分配（从文件加载代码/数据）
2. **写保护页** → Copy-On-Write（COW优化）
3. **无效访问** → 终止进程（SIGSEGV）

这是**Linux风格的实现**！

 📖 第三课：异常的栈帧结构

### 3.1 普通异常的栈帧

**CPU 自动压栈：**

```
异常发生时，CPU 压入：
┌──────────┐
│ EFLAGS   │ ← SS:ESP+12
├──────────┤
│ CS       │ ← SS:ESP+8
├──────────┤
│ EIP      │ ← SS:ESP+4
└──────────┘ ← SS:ESP
```

**对应 C 结构体：**

```c
struct interrupt_frame {
    uint32_t eip;       // 触发异常的指令地址
    uint32_t cs;        // 代码段
    uint32_t eflags;    // 标志寄存器
};
```

### 3.2 带错误码的异常

**某些异常会压入错误码：**

```
异常 8, 10-14, 17 会压入错误码

栈帧：
┌──────────┐
│ EFLAGS   │ ← SS:ESP+16
├──────────┤
│ CS       │ ← SS:ESP+12
├──────────┤
│ EIP      │ ← SS:ESP+8
├──────────┤
│ ERROR    │ ← SS:ESP+4  ← 额外的错误码！
└──────────┘ ← SS:ESP
```

**对应结构体：**

```c
struct interrupt_frame_with_error {
    uint32_t error_code;  // 错误码
    uint32_t eip;
    uint32_t cs;
    uint32_t eflags;
};
```

**为什么有的有错误码，有的没有？**

```
有错误码的异常（8个）：
  8  - Double Fault
  10 - Invalid TSS
  11 - Segment Not Present
  12 - Stack Fault
  13 - General Protection
  14 - Page Fault
  17 - Alignment Check
  30 - Security Exception
  
其他 24 个：没有错误码
```

## 📖 第四课：实现异常处理

### 4.1 异常处理程序的统一结构

**问题：** 有的异常有错误码，有的没有，如何统一处理？

**解决方案：** 手动补齐

```asm
; 没有错误码的异常（比如异常 0）
isr0:
    push 0           ; 手动压入 dummy 错误码
    push 0           ; 压入异常号
    jmp isr_common

; 有错误码的异常（比如异常 13）
isr13:
    ; CPU 已经压入错误码
    push 13          ; 压入异常号
    jmp isr_common

; 统一处理入口
isr_common:
    pusha           ; 保存所有通用寄存器
    push ds
    push es
    push fs
    push gs
    
    ; 设置内核数据段
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    
    ; 调用 C 处理函数
    push esp        ; 传递栈指针（所有寄存器信息）
    call exception_dispatcher
    add esp, 4
    
    ; 恢复寄存器
    pop gs
    pop fs
    pop es
    pop ds
    popa
    
    add esp, 8      ; 清理错误码和异常号
    iret
```

**现在栈帧统一了：**

```c
struct exception_frame {
    // 我们压入的
    uint32_t gs, fs, es, ds;
    uint32_t edi, esi, ebp, esp, ebx, edx, ecx, eax; // pusha
    uint32_t int_no;      // 异常号
    uint32_t err_code;    // 错误码（可能是 dummy）
    
    // CPU 压入的
    uint32_t eip;
    uint32_t cs;
    uint32_t eflags;
    
    // 如果特权级变化，还有：
    uint32_t user_esp;
    uint32_t ss;
};
```

### 4.2 生成256个中断入口

**问题：** 需要为每个中断写一个 `isr_N`？

**解决：** 使用宏！

```asm
; 定义宏：无错误码的异常
%macro ISR_NOERRCODE 1
    global isr%1
    isr%1:
        push 0           ; Dummy 错误码
        push %1          ; 中断号
        jmp isr_common
%endmacro

; 定义宏：有错误码的异常
%macro ISR_ERRCODE 1
    global isr%1
    isr%1:
        ; CPU 已压入错误码
        push %1          ; 中断号
        jmp isr_common
%endmacro

; 使用宏生成
ISR_NOERRCODE 0   ; 除零
ISR_NOERRCODE 1   ; 调试
ISR_NOERRCODE 2   ; NMI
; ...
ISR_ERRCODE 8     ; Double Fault
ISR_ERRCODE 10    ; Invalid TSS
; ...
ISR_NOERRCODE 32  ; IRQ 0 (定时器)
ISR_NOERRCODE 33  ; IRQ 1 (键盘)
; ...
```

**在 C 中注册：**

```c
// 外部声明
extern void isr0(void);
extern void isr1(void);
// ... isr0 到 isr255

void idt_init(void)
{
    // 注册所有异常
    idt_set_gate(0, (uint32_t)isr0, 0x08, 0x8E);
    idt_set_gate(1, (uint32_t)isr1, 0x08, 0x8E);
    // ...
    idt_set_gate(13, (uint32_t)isr13, 0x08, 0x8E);
    idt_set_gate(14, (uint32_t)isr14, 0x08, 0x8E);
    // ...
}
```

## 📖 第五课：实现具体的异常处理器

### 5.1 异常分发器（EduOS实际实现）

基于 `kernel/arch/i386/exception.c`:

```c
/* 异常名称表（32个CPU异常） */
static const char *exception_messages[32] = {
    "Division By Zero",                 // 0
    "Debug",                            // 1
    "Non Maskable Interrupt",           // 2
    "Breakpoint",                       // 3
    "Overflow",                         // 4
    "Bound Range Exceeded",             // 5
    "Invalid Opcode",                   // 6
    "Device Not Available",             // 7
    "Double Fault",                     // 8
    "Coprocessor Segment Overrun",      // 9
    "Invalid TSS",                      // 10
    "Segment Not Present",              // 11
    "Stack-Segment Fault",              // 12
    "General Protection Fault",         // 13
    "Page Fault",                       // 14
    "Reserved",                         // 15
    "x87 FPU Error",                    // 16
    "Alignment Check",                  // 17
    "Machine Check",                    // 18
    "SIMD Floating-Point",              // 19
    "Virtualization",                   // 20
    "Control Protection",               // 21
    "Reserved", ... "Reserved",         // 22-31
};

/* 哪些异常有错误码 */
static const bool exception_has_error_code[32] = {
    false, false, false, false, false, false, false, false,  // 0-7
    true,  false, true,  true,  true,  true,  true,  false, // 8-15
    false, true,  false, false, false, true,  false, false, // 16-23
    false, false, false, false, false, false, false, false, // 24-31
};

void exception_handler(struct interrupt_frame *frame)
{
    uint32_t int_no = frame->int_no;
    
    /* Linux风格：异常处理期间禁止调度 */
    extern void scheduler_disable(void);
    extern void scheduler_enable_noschedule(void);
    scheduler_disable();  // ← 关键！防止在处理异常时被调度
    
    /* Page Fault特殊快速路径：不打印，直接处理 */
    if (int_no == EXCEPTION_PF) {
        if (handle_page_fault(frame) == 0) {
            scheduler_enable_noschedule();
            return;  /* 成功处理，静默返回 */
        }
    }
    
    /* 其他异常：显示详细信息 */
    vga_set_color(VGA_COLOR_LIGHT_RED, VGA_COLOR_BLACK);
    
    kprintf("\n╔════════════════════════════════╗\n");
    kprintf("║   CPU EXCEPTION DETECTED       ║\n");
    kprintf("╚════════════════════════════════╝\n");
    
    kprintf("\nException #%d: %s\n", int_no, exception_messages[int_no]);
    if (exception_has_error_code[int_no]) {
        kprintf("Error Code: 0x%08x\n", frame->err_code);
    }
    
    /* 调用具体处理器 */
    switch (int_no) {
        case 0: handle_divide_error(frame); break;
        case 6: handle_invalid_opcode(frame); break;
        case 8: handle_double_fault(frame); break;
        case 13: handle_general_protection(frame); break;
        case 14: handle_page_fault(frame); break;
        default:
            kprintf("No specific handler\n");
            break;
    }
    
    /* 打印寄存器和栈回溯 */
    print_registers(frame);
    print_stack_trace((uint32_t*)frame->ebp, 10);
    
    vga_set_color(VGA_COLOR_LIGHT_GREY, VGA_COLOR_BLACK);
    
    /* 进入无限循环或panic */
    while(1) { asm volatile("hlt"); }
}
```

**EduOS的关键改进：**

1. ✅ **快速路径优化** - Page Fault静默处理（性能）
2. ✅ **调度器锁** - 异常处理期间禁止调度（稳定性）  
3. ✅ **VMA按需分配** - 只加载真正需要的页面（内存优化）
4. ✅ **COW机制** - 写时复制（fork优化）

### 5.3 双重故障异常 (#DF, 8)（最危险！）

基于 `kernel/arch/i386/exception.c`:

```c
static void handle_double_fault(struct interrupt_frame *frame)
{
    /* 立即输出到串口，避免kprintf可能失败 */
    extern void serial_putc(uint16_t port, char c);
    serial_putc(0x3F8, 'D');
    serial_putc(0x3F8, 'F');
    serial_putc(0x3F8, '!');
    serial_putc(0x3F8, '\n');
    
    kprintf("\n!!! CRITICAL: Double Fault !!!\n");
    kprintf("Error Code: 0x%08x\n", frame->err_code);
    kprintf("This usually indicates a serious kernel bug!\n");
}
```

**什么是Double Fault？**

```
场景1：处理异常时又发生异常

例如：
  1. Page Fault发生
  2. 跳转到Page Fault处理程序
  3. 处理程序的栈无效（也触发Page Fault）
  4. → Double Fault！

场景2：IDT配置错误

  1. 异常发生
  2. 查IDT，发现处理程序地址无效
  3. → General Protection Fault
  4. 再次查IDT（处理GP）
  5. GP处理程序也无效
  6. → Double Fault！

如果Double Fault也失败 → Triple Fault → CPU重启！
```

**调试技巧：**

```c

// 或者确保异常处理程序栈总是有效
```

```c
void print_stack_trace(void)
{
    uint32_t *ebp;
    asm("mov %%ebp, %0" : "=r"(ebp));
    
    kprintf("\nStack Trace:\n");
    
    for (int frame = 0; frame < 10 && ebp; frame++) {
        uint32_t eip = ebp[1];  // 返回地址

    }
}
```

### 练习4：测试Page Fault（EduOS真实示例）

**场景：加载ELF程序时的按需分配**

```c
/* 用户程序访问未映射的代码页 */
void _start(void)
{
    // 第一条指令：0x08000000
    // 这个地址还没映射！
    printf("Hello World\n");  
    // ↑ 触发Page Fault
    // ↓ VMA按需从/hello.elf加载代码
    // ↓ 返回继续执行
    // ✓ 程序正常运行
}
```

**实际Page Fault处理流程（EduOS）：**

```
1. CPU执行到0x08000000（未映射）
   ↓
2. 触发Page Fault (#PF, 14)
   ↓
3. handle_page_fault():
   - 读取CR2 = 0x08000000
   - 查找VMA（虚拟内存区域）
   - 找到：0x08000000-0x08003000 (代码段，文件映射)
   ↓
4. vma_handle_page_fault():
   - 分配物理页面
   - 从/hello.elf读取4KB数据
   - 建立页表映射：0x08000000 → 物理页
   - 刷新TLB（invlpg）
   ↓
5. 返回0（成功）
   ↓
6. exception_handler静默返回
   ↓
7. IRET返回用户程序
   ↓
8. 重新执行指令 → 成功！代码已加载
```

这就是**Linux的demand paging（按需分页）**！

### 核心概念

✅ **异常** - CPU 检测到的错误

✅ **32 个 CPU 异常** - 0-31 保留

### 异常列表速查

| 常见异常 | 编号 | 错误码 | 原因 |
|---------|------|--------|------|
| 除零 | 0 | 无 | 除法指令除数为0 |
| 调试 | 1 | 无 | 调试器断点 |
| 断点 | 3 | 无 | INT 3指令 |

### EduOS的异常处理特色

**1. Page Fault快速路径**
```c
if (int_no == EXCEPTION_PF) {
    if (handle_page_fault(frame) == 0) {
        return;  // 静默返回，不打印
    }
}
```
- ✅ 性能优化：每次Page Fault不打印日志
- ✅ 实测：加载GUI程序触发768次Page Fault，耗时<1秒

**2. 调度器锁机制**
```c
scheduler_disable();  // 异常处理期间禁止调度
// ... 处理异常 ...
scheduler_enable_noschedule();  // 解锁
```
- ✅ 避免在Page Fault中被定时器中断打断
- ✅ 防止CR3切换破坏异常处理上下文

**3. VMA（虚拟内存区域）按需分配**
```c
struct vma *vma = vma_find(proc->vma_list, fault_addr);
if (vma) {
    vma_handle_page_fault(vma, fault_addr, proc->page_dir);
}
```
- ✅ 代码段：从ELF文件加载
- ✅ 数据段：从ELF文件加载
- ✅ BSS段：清零
- ✅ 栈：按需扩展
- ✅ 设备：映射framebuffer物理内存

**4. Copy-On-Write优化**
```c
if (present && write) {
    // 页存在但写保护 → COW
    uint32_t new_page = pmm_alloc_frame();
    memcpy(new_page, old_page, 4096);
    vmm_map_page(vaddr, new_page, WRITABLE);
    return 0;
}
```
- ✅ fork()时父子进程共享页面
- ✅ 写入时才复制（节省内存）
