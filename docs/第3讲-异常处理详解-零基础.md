## 📖 第一课：什么是异常

### 1.1 从错误说起

**在普通程序中：**

```c
int main() {
    int x = 10;
    int y = 0;
    int z = x / y;  // 除以零！
    
    // 程序崩溃...
}
```

**在 Windows 中看到：**
```
╔════════════════════════════════╗
║ 程序 xxx.exe 遇到问题需要关闭  ║
║                                ║
║ [发送错误报告]  [不发送]      ║
╚════════════════════════════════╝
```

**在操作系统内核中：**
```
没有 Windows 来捕获错误！
除以零会发生什么？

答案：CPU 触发异常！
  → 查 IDT 中断 0
  → 跳转到异常处理程序
  → 你的代码决定怎么办
```

---

### 1.2 异常 vs 中断

**核心区别：**

| 特性 | 中断（Interrupt） | 异常（Exception） |
|------|------------------|-------------------|
| 来源 | 外部硬件 | CPU 内部 |
| 时机 | 异步（随时） | 同步（执行指令时） |
| 可预测 | 不可预测 | 可预测 |
| 可屏蔽 | 部分可以 | 不可以 |
| 示例 | 键盘、定时器 | 除零、缺页 |

**异步 vs 同步：**

```
中断（异步）：
  CPU 正在执行代码...
  突然！定时器中断  ← 不知道什么时候发生
  
异常（同步）：
  CPU 执行 DIV 指令
  → 发现除数是 0
  → 立即触发异常  ← 总是在这条指令
```

**类比：**
```
中断 = 门铃响了
  → 不知道什么时候会响
  → 正在做任何事情都可能被打断
  
异常 = 走路摔倒了
  → 明确是在"走路"这个动作时
  → 可重现（再走一次还会摔）
```

### 1.3 x86 的 32 个异常

**异常编号 0-31（CPU 保留）：**

| 编号 | 名称 | 符号 | 说明 |
|------|------|------|------|
| 0 | Divide Error | #DE | 除零或除法溢出 |
| 1 | Debug | #DB | 调试异常 |
| 2 | NMI | - | 不可屏蔽中断 |
| 3 | Breakpoint | #BP | INT 3 指令 |
| 4 | Overflow | #OF | INTO 指令 |
| 5 | Bound Range | #BR | BOUND 指令 |
| 6 | Invalid Opcode | #UD | 无效指令 |
| 7 | Device Not Available | #NM | FPU 不可用 |
| 8 | Double Fault | #DF | 双重故障 |
| 9 | - | - | 协处理器段越界 |
| 10 | Invalid TSS | #TS | 无效 TSS |
| 11 | Segment Not Present | #NP | 段不存在 |
| 12 | Stack Fault | #SS | 栈段故障 |
| 13 | General Protection | #GP | 保护故障 |
| 14 | Page Fault | #PF | 缺页异常 |
| 15 | - | - | Intel 保留 |
| 16 | x87 FPU Error | #MF | 浮点错误 |
| 17 | Alignment Check | #AC | 对齐检查 |
| 18 | Machine Check | #MC | 机器检查 |
| 19 | SIMD FP Exception | #XM | SIMD 浮点异常 |
| 20-31 | - | - | Intel 保留 |

**最常见的 5 个异常：**
1. #DE (0)  - 除零
2. #UD (6)  - 无效指令
3. #GP (13) - 保护故障（最常见！）
4. #PF (14) - 缺页异常
5. #DF (8)  - 双重故障（最危险！）

## 📖 第二课：异常详解

### 2.1 除零异常 (#DE, 0)

**触发条件：**

```c
int x = 10;
int y = 0;
int z = x / y;  ← 触发异常 0
```

**或者：**
```asm
mov eax, 10
mov ebx, 0
div ebx         ; 触发异常 0
```

**异常处理：**

```c
void divide_error_handler(void)
{
    kprintf("╔════════════════════════════════╗\n");
    kprintf("║ EXCEPTION: Divide by Zero (#DE)║\n");
    kprintf("║                                ║\n");
    kprintf("║ 程序尝试除以零！              ║\n");
    kprintf("╚════════════════════════════════╝\n");
    
    // 选项1：终止当前进程
    process_kill_current();
    
    // 选项2：忽略（危险！）
    // 选项3：系统崩溃
    panic("Divide by zero");
}
```

---

### 2.2 保护故障 (#GP, 13)

**#GP = General Protection Fault**

**这是最常见的异常！各种错误都可能触发：**

**原因1：访问不存在的内存**
```c
int *ptr = (int*)0x0;  // 空指针
int value = *ptr;       // 触发 #GP (如果没启用分页)
```

**原因2：特权级违规**
```c
// 用户态程序（Ring 3）
asm("cli");  // CLI 是特权指令
             // 触发 #GP！
```

**原因3：段错误**
```asm
mov ax, 0x1234  ; 无效的段选择子
mov ds, ax      ; 触发 #GP
```

**原因4：访问超出段限制**
```
段限制 = 0xFFFF (64KB)
访问偏移 = 0x10000 (64KB+1)
  → 触发 #GP
```

**异常处理：**

```c
void general_protection_handler(struct interrupt_frame *frame)
{
    kprintf("╔════════════════════════════════╗\n");
    kprintf("║ EXCEPTION: General Protection  ║\n");
    kprintf("╚════════════════════════════════╝\n");
    
    kprintf("错误码: 0x%X\n", frame->error_code);
    kprintf("CS:EIP = 0x%04X:0x%08X\n", frame->cs, frame->eip);
    kprintf("EFLAGS = 0x%08X\n", frame->eflags);
    
    // 打印栈回溯
    print_stack_trace();
    
    // 终止进程或系统
    panic("General Protection Fault");
}
```

**错误码的含义：**

```
错误码（16位）：

Bit 0:   EXT  - 外部事件
Bit 1:   IDT  - IDT中的描述符
Bit 2:   TI   - GDT(0) 还是 LDT(1)
Bit 3-15: Index - 段选择子索引

示例：
  错误码 = 0x0002
  → Bit 1 = 1 → IDT 中的描述符
  → Index = 0 → IDT[0]
  → 说明是中断 0 的描述符有问题
```

### 2.3 缺页异常 (#PF, 14)

**#PF = Page Fault**

**这是内存管理的核心！**

**触发时机：**
```
启用分页后：
  所有内存访问都通过页表
  
  如果访问的虚拟地址没有映射：
    → 触发缺页异常
```

**示例：**
```c
// 假设 0x80000000 没有映射
int *ptr = (int*)0x80000000;
int value = *ptr;  // 触发 #PF
```

**CR2 寄存器：**

```
CR2 = 触发缺页的虚拟地址

在处理程序中：
  asm("mov %%cr2, %0" : "=r"(fault_addr));
  kprintf("Page fault at: 0x%08X\n", fault_addr);
```

**错误码（特殊）：**

```
Bit 0: P  - Present (0=页不存在, 1=保护违规)
Bit 1: W/R - Write/Read (0=读, 1=写)
Bit 2: U/S - User/Supervisor (0=内核态, 1=用户态)
Bit 3: RSVD - 保留位错误
Bit 4: I/D - Instruction/Data (0=数据, 1=取指令)

示例：
  错误码 = 0x02 = 0000 0010
  → P=0（页不存在）
  → W/R=1（尝试写入）
  
  说明：程序尝试写入一个未映射的页
```

**缺页处理：**

```c
void page_fault_handler(struct interrupt_frame *frame)
{
    // 读取故障地址
    uint32_t fault_addr;
    asm("mov %%cr2, %0" : "=r"(fault_addr));
    
    uint32_t err_code = frame->error_code;
    
    kprintf("Page Fault at 0x%08X\n", fault_addr);
    kprintf("Error code: 0x%X ", err_code);
    
    if (!(err_code & 0x1)) kprintf("[Page Not Present] ");
    if (err_code & 0x2) kprintf("[Write] "); else kprintf("[Read] ");
    if (err_code & 0x4) kprintf("[User Mode] "); else kprintf("[Kernel Mode] ");
    kprintf("\n");
    
    // 处理方案：
    
    // 方案1：页不存在 → 分配页
    if (!(err_code & 0x1)) {
        uint32_t page = pmm_alloc_frame();
        vmm_map_page(fault_addr, page, PAGE_PRESENT | PAGE_WRITABLE);
        return;  // 返回后重新执行指令
    }
    
    // 方案2：保护违规 → 终止进程
    panic("Page Protection Violation");
}
```

 📖 第三课：异常的栈帧结构

### 3.1 普通异常的栈帧

**CPU 自动压栈：**

```
异常发生时，CPU 压入：
┌──────────┐
│ EFLAGS   │ ← SS:ESP+12
├──────────┤
│ CS       │ ← SS:ESP+8
├──────────┤
│ EIP      │ ← SS:ESP+4
└──────────┘ ← SS:ESP
```

**对应 C 结构体：**

```c
struct interrupt_frame {
    uint32_t eip;       // 触发异常的指令地址
    uint32_t cs;        // 代码段
    uint32_t eflags;    // 标志寄存器
};
```

### 3.2 带错误码的异常

**某些异常会压入错误码：**

```
异常 8, 10-14, 17 会压入错误码

栈帧：
┌──────────┐
│ EFLAGS   │ ← SS:ESP+16
├──────────┤
│ CS       │ ← SS:ESP+12
├──────────┤
│ EIP      │ ← SS:ESP+8
├──────────┤
│ ERROR    │ ← SS:ESP+4  ← 额外的错误码！
└──────────┘ ← SS:ESP
```

**对应结构体：**

```c
struct interrupt_frame_with_error {
    uint32_t error_code;  // 错误码
    uint32_t eip;
    uint32_t cs;
    uint32_t eflags;
};
```

**为什么有的有错误码，有的没有？**

```
有错误码的异常（8个）：
  8  - Double Fault
  10 - Invalid TSS
  11 - Segment Not Present
  12 - Stack Fault
  13 - General Protection
  14 - Page Fault
  17 - Alignment Check
  30 - Security Exception
  
其他 24 个：没有错误码
```

## 📖 第四课：实现异常处理

### 4.1 异常处理程序的统一结构

**问题：** 有的异常有错误码，有的没有，如何统一处理？

**解决方案：** 手动补齐

```asm
; 没有错误码的异常（比如异常 0）
isr0:
    push 0           ; 手动压入 dummy 错误码
    push 0           ; 压入异常号
    jmp isr_common

; 有错误码的异常（比如异常 13）
isr13:
    ; CPU 已经压入错误码
    push 13          ; 压入异常号
    jmp isr_common

; 统一处理入口
isr_common:
    pusha           ; 保存所有通用寄存器
    push ds
    push es
    push fs
    push gs
    
    ; 设置内核数据段
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    
    ; 调用 C 处理函数
    push esp        ; 传递栈指针（所有寄存器信息）
    call exception_dispatcher
    add esp, 4
    
    ; 恢复寄存器
    pop gs
    pop fs
    pop es
    pop ds
    popa
    
    add esp, 8      ; 清理错误码和异常号
    iret
```

**现在栈帧统一了：**

```c
struct exception_frame {
    // 我们压入的
    uint32_t gs, fs, es, ds;
    uint32_t edi, esi, ebp, esp, ebx, edx, ecx, eax; // pusha
    uint32_t int_no;      // 异常号
    uint32_t err_code;    // 错误码（可能是 dummy）
    
    // CPU 压入的
    uint32_t eip;
    uint32_t cs;
    uint32_t eflags;
    
    // 如果特权级变化，还有：
    uint32_t user_esp;
    uint32_t ss;
};
```

### 4.2 生成256个中断入口

**问题：** 需要为每个中断写一个 `isr_N`？

**解决：** 使用宏！

```asm
; 定义宏：无错误码的异常
%macro ISR_NOERRCODE 1
    global isr%1
    isr%1:
        push 0           ; Dummy 错误码
        push %1          ; 中断号
        jmp isr_common
%endmacro

; 定义宏：有错误码的异常
%macro ISR_ERRCODE 1
    global isr%1
    isr%1:
        ; CPU 已压入错误码
        push %1          ; 中断号
        jmp isr_common
%endmacro

; 使用宏生成
ISR_NOERRCODE 0   ; 除零
ISR_NOERRCODE 1   ; 调试
ISR_NOERRCODE 2   ; NMI
; ...
ISR_ERRCODE 8     ; Double Fault
ISR_ERRCODE 10    ; Invalid TSS
; ...
ISR_NOERRCODE 32  ; IRQ 0 (定时器)
ISR_NOERRCODE 33  ; IRQ 1 (键盘)
; ...
```

**在 C 中注册：**

```c
// 外部声明
extern void isr0(void);
extern void isr1(void);
// ... isr0 到 isr255

void idt_init(void)
{
    // 注册所有异常
    idt_set_gate(0, (uint32_t)isr0, 0x08, 0x8E);
    idt_set_gate(1, (uint32_t)isr1, 0x08, 0x8E);
    // ...
    idt_set_gate(13, (uint32_t)isr13, 0x08, 0x8E);
    idt_set_gate(14, (uint32_t)isr14, 0x08, 0x8E);
    // ...
}
```

## 📖 第五课：实现具体的异常处理器

### 5.1 异常分发器

```c
// 异常名称
const char *exception_messages[] = {
    "Divide by Zero",
    "Debug",
    "Non-Maskable Interrupt",
    "Breakpoint",
    "Overflow",
    "Bound Range Exceeded",
    "Invalid Opcode",
    "Device Not Available",
    "Double Fault",
    "Coprocessor Segment Overrun",
    "Invalid TSS",
    "Segment Not Present",
    "Stack Fault",
    "General Protection Fault",
    "Page Fault",
    "Reserved",
    "x87 FPU Error",
    "Alignment Check",
    "Machine Check",
    "SIMD Floating-Point Exception",
    // ... 更多
};

void exception_dispatcher(struct exception_frame *frame)
{
    if (frame->int_no < 32) {
        // CPU 异常
        kprintf("\n");
        kprintf("════════════════════════════════\n");
        kprintf("CPU EXCEPTION: %s (#%d)\n", 
                exception_messages[frame->int_no],
                frame->int_no);
        kprintf("════════════════════════════════\n");
        
        kprintf("Error Code: 0x%X\n", frame->err_code);
        kprintf("EIP: 0x%08X\n", frame->eip);
        kprintf("CS:  0x%04X\n", frame->cs);
        kprintf("EFLAGS: 0x%08X\n", frame->eflags);
        kprintf("EAX: 0x%08X  EBX: 0x%08X\n", frame->eax, frame->ebx);
        kprintf("ECX: 0x%08X  EDX: 0x%08X\n", frame->ecx, frame->edx);
        kprintf("ESI: 0x%08X  EDI: 0x%08X\n", frame->esi, frame->edi);
        kprintf("EBP: 0x%08X  ESP: 0x%08X\n", frame->ebp, frame->esp);
        
        // 调用具体处理函数
        switch (frame->int_no) {
            case 0:
                divide_error_handler(frame);
                break;
            case 13:
                general_protection_handler(frame);
                break;
            case 14:
                page_fault_handler(frame);
                break;
            default:
                panic("Unhandled exception");
        }
    } else {
        // 硬件中断（后面处理）
    }
}
```

## 📖 第六课：调试技巧

### 6.1 栈回溯（Stack Trace）

**作用：** 显示函数调用链

```c
void print_stack_trace(void)
{
    uint32_t *ebp;
    asm("mov %%ebp, %0" : "=r"(ebp));
    
    kprintf("\nStack Trace:\n");
    
    for (int frame = 0; frame < 10 && ebp; frame++) {
        uint32_t eip = ebp[1];  // 返回地址
        
        if (eip == 0) break;
        
        kprintf("  [%d] 0x%08X\n", frame, eip);
        
        ebp = (uint32_t*)ebp[0];  // 前一个 EBP
    }
}
```

**输出示例：**
```
Stack Trace:
  [0] 0xC0101234  ← function_c
  [1] 0xC0105678  ← function_b
  [2] 0xC0109ABC  ← function_a
  [3] 0xC0100DEF  ← kernel_main
```

### 6.2 寄存器转储

```c
void dump_registers(struct exception_frame *frame)
{
    kprintf("\nRegister Dump:\n");
    kprintf("EAX=0x%08X  EBX=0x%08X  ECX=0x%08X  EDX=0x%08X\n",
            frame->eax, frame->ebx, frame->ecx, frame->edx);
    kprintf("ESI=0x%08X  EDI=0x%08X  EBP=0x%08X  ESP=0x%08X\n",
            frame->esi, frame->edi, frame->ebp, frame->esp);
    kprintf("EIP=0x%08X  EFLAGS=0x%08X\n",
            frame->eip, frame->eflags);
    kprintf("CS=0x%04X  DS=0x%04X  ES=0x%04X  SS=0x%04X\n",
            frame->cs, frame->ds, frame->es, frame->ss);
}
```

### 练习2：安全的除法

```c
int safe_divide(int a, int b, int *result)
{
    if (b == 0) {
        return -1;  // 错误
    }
    
    *result = a / b;
    return 0;  // 成功
}

    kprintf("Error: division by zero\n");
}
```

### 练习3：自定义异常处理

```c
// 除零时不崩溃，而是返回 0
void custom_divide_handler(struct exception_frame *frame)
{
    kprintf("Warning: Division by zero, returning 0\n");
    
    // 修改 EAX（除法结果寄存器）
    frame->eax = 0;
    
    // 跳过出错的指令（假设是 2 字节）
    frame->eip += 2;
    
    // 返回后会继续执行
}
```

## 📊 异常处理策略

### 策略1：终止进程

```c
if (in_user_mode(frame)) {
    kprintf("Terminating process %d\n", current_pid);
    process_kill(current_pid);
    schedule_next();
} else {
    panic("Kernel exception!");
}
```

### 策略2：修复并继续

```c
if (can_fix(frame)) {
    fix_problem(frame);
    return;  // 重新执行指令
} else {
    panic("Unfixable exception");
}
```

### 策略3：记录日志

```c
void exception_handler(struct exception_frame *frame)
{
    log_exception(frame);
    
    if (is_critical(frame->int_no)) {
        panic("Critical exception");
    } else {
        kprintf("Warning: Non-critical exception\n");
    }
}
```

## 🎓 总结

### 核心概念

✅ **异常** - CPU 检测到的错误  
✅ **异常 vs 中断** - 同步 vs 异步  
✅ **32 个 CPU 异常** - 0-31 保留  
✅ **错误码** - 提供额外信息  
✅ **栈帧结构** - 保存执行状态  
✅ **异常处理** - 修复、终止或崩溃

### 异常列表速查

| 常见异常 | 编号 | 错误码 | 原因 |
