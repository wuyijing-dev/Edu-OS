## 🎯 核心概念

### 1. 为什么需要高级调度算法？

**第5章的简单FIFO调度的问题**：

```
问题1：所有进程平等对待
- 交互式程序（如shell）需要快速响应
- 后台计算任务可以慢一点
- 但FIFO对所有进程一视同仁

问题2：没有优先级
- 重要任务和不重要任务获得同样的CPU时间
- 无法满足实时系统的需求

问题3：短作业等待长
- 短任务可能被长任务阻塞很久
- 导致平均响应时间增加
```

**解决方案**：多种调度算法满足不同需求

### 2. 调度算法分类

```
调度算法族谱：

批处理系统：
├── 先来先服务（FCFS）
├── 最短作业优先（SJF）
└── 最短剩余时间优先（SRTF）

交互式系统：
├── 轮转调度（RR）
├── 优先级调度
├── 多级队列
└── 多级反馈队列（MLFQ）⭐

实时系统：
├── 速率单调（RM）
├── 最早截止期限（EDF）
├── SCHED_FIFO
└── SCHED_RR

现代操作系统：
├── Linux CFS（完全公平调度器）⭐
├── Windows 优先级调度
└── macOS Mach调度器
```

### 3. 调度评价指标

**如何评价一个调度算法的好坏？**

```c
/* CPU利用率 */
CPU利用率 = (CPU工作时间 / 总时间) × 100%
目标：最大化（接近100%）

/* 吞吐量 */
吞吐量 = 单位时间内完成的进程数
目标：最大化

/* 周转时间 */
周转时间 = 完成时间 - 到达时间
目标：最小化

/* 等待时间 */
等待时间 = 周转时间 - 执行时间
目标：最小化

/* 响应时间 */
响应时间 = 首次执行时间 - 到达时间
目标：最小化（对交互式系统很重要）
```

**举例**：

```
3个进程到达：
P1: 执行时间24ms
P2: 执行时间3ms
P3: 执行时间3ms

FCFS调度：
P1 ──────────────────────── (0-24ms)
P2 ─── (24-27ms)
P3 ─── (27-30ms)

平均等待时间 = (0 + 24 + 27) / 3 = 17ms

SJF调度（最短优先）：
P2 ─── (0-3ms)
P3 ─── (3-6ms)
P1 ──────────────────────── (6-30ms)

平均等待时间 = (6 + 0 + 3) / 3 = 3ms  ✅ 更好！
```

### 1.1 调度策略枚举

我们将支持多种调度策略：

```c
/* 调度策略 */
typedef enum {
    SCHED_NORMAL = 0,      /* 普通分时调度（CFS风格） */
    SCHED_FIFO = 1,        /* 实时FIFO调度 */
    SCHED_RR = 2,          /* 实时轮转调度 */
    SCHED_BATCH = 3,       /* 批处理调度（低优先级） */
    SCHED_IDLE = 5,        /* 空闲调度（最低优先级） */
} sched_policy_t;
```

**策略说明**：

| 策略 | 用途 | 特点 |
|------|------|------|
| SCHED_NORMAL | 普通进程 | 动态优先级，公平调度 |
| SCHED_FIFO | 实时任务 | 固定优先级，不抢占（除非更高优先级） |
| SCHED_RR | 实时任务 | 固定优先级，时间片轮转 |
| SCHED_BATCH | 后台任务 | 低优先级，大时间片 |
| SCHED_IDLE | 空闲任务 | 最低优先级，只有CPU空闲时运行 |

### 1.2 优先级系统

**Linux风格的优先级**：

```
优先级范围：0-139
├── 实时优先级：0-99（数字越小越高）
└── 普通优先级：100-139（对应nice值-20到+19）

实时优先级（0-99）：
0  ← 最高优先级（实时）
...
99 ← 最低实时优先级

普通优先级（100-139）：
100 ← nice -20 (最高普通优先级)
120 ← nice 0   (默认)
139 ← nice +19 (最低普通优先级)
```

**Nice值**：

```c
/* Nice值：-20 到 +19 */
nice = 0   // 默认，普通优先级
nice = -20 // 最高普通优先级（只有root可以设置负值）
nice = +19 // 最低普通优先级

/* Nice值转优先级 */
priority = 120 + nice;  // 范围：100-139
```

## 🏗️ 第2部分：优先级调度

### 2.1 优先级调度原理

**基本思想**：每个进程有一个优先级，CPU总是分配给最高优先级的就绪进程。

```
优先级队列（32个）：

Priority 0  [P1] → [P5] → NULL      ← 最高优先级
Priority 1  NULL
Priority 2  [P2] → NULL
...
Priority 10 [P3] → [P4] → [P6] → NULL
...
Priority 31 [P7] → NULL             ← 最低优先级

调度规则：
1. 选择最高优先级的非空队列
2. 从该队列头部取出进程
3. 进程运行完时间片后，放回队列尾部
```

**优点**：
- ✅ 重要任务优先执行
- ✅ 实现简单

**缺点**：
- ❌ **饿死问题**：低优先级进程可能永远得不到CPU
- ❌ **优先级反转**：高优先级进程等待低优先级进程释放资源

### 2.2 优先级调度实现

**数据结构**：

```c
#define MAX_PRIORITIES 32

/* 优先级调度器 */
struct priority_scheduler {
    struct process *queues[MAX_PRIORITIES];  /* 32个优先级队列 */
    uint32_t bitmap;                         /* 位图标记哪些队列非空 */
    uint32_t ready_count[MAX_PRIORITIES];    /* 每个队列的进程数 */
};
```

**选择下一个进程**：

```c
struct process *pick_next_priority(void)
{
    /* 使用位运算快速找到最高优先级 */
    if (bitmap == 0) {
        return idle_process;
    }
    
    /* ffs: find first set bit（找到第一个为1的位） */
    int highest_priority = __builtin_ffs(bitmap) - 1;
    
    /* 从该优先级队列取出第一个进程 */
    struct process *next = queues[highest_priority];
    
    /* 从队列中移除 */
    queues[highest_priority] = next->next;
    if (queues[highest_priority] == NULL) {
        bitmap &= ~(1 << highest_priority);  /* 清除该位 */
    }
    
    return next;
}
```

**防止饿死：优先级老化**

```c
/* 优先级老化：定期提升等待时间长的进程的优先级 */
void priority_aging(void)
{
    uint64_t current_time = timer_get_ticks();
    
    for (int pri = 0; pri < MAX_PRIORITIES; pri++) {
        struct process *proc = queues[pri];
        while (proc) {
            /* 如果进程等待超过100个tick，提升优先级 */
            if (current_time - proc->last_run > 100) {
                if (pri > 0) {
                    /* 移到更高优先级队列 */
                    remove_from_queue(proc, pri);
                    add_to_queue(proc, pri - 1);
                }
            }
            proc = proc->next;
        }
    }
}
```

## 🏗️ 第3部分：多级反馈队列（MLFQ）

### 3.1 MLFQ原理

**核心思想**：根据进程的行为动态调整优先级

```
多级反馈队列：

Queue 0 (最高优先级, 时间片=8ms)
┌─────┬─────┬─────┐
│ P1  │ P3  │     │
└─────┴─────┴─────┘
      ↓ 用完时间片，降级
      
Queue 1 (中等优先级, 时间片=16ms)
┌─────┬─────┬─────┐
│ P2  │ P5  │     │
└─────┴─────┴─────┘
      ↓ 用完时间片，降级
      
Queue 2 (低优先级, 时间片=32ms)
┌─────┬─────┬─────┐
│ P4  │ P6  │     │
└─────┴─────┴─────┘
```

**MLFQ规则**：

```
规则1：优先级高的队列先运行
规则2：同一队列内使用RR算法
规则3：新进程进入最高优先级队列
规则4：进程用完时间片，降低一级优先级
规则5：进程主动让出CPU（I/O等），保持优先级
规则6：周期性地将所有进程提升到最高级（防止饿死）
```

**适应不同类型的进程**：

```
交互式进程（I/O密集）：
- 频繁主动让出CPU
- 保持在高优先级队列
- 响应快 ✅

CPU密集型进程：
- 总是用完时间片
- 逐渐降到低优先级队列
- 不影响交互式进程 ✅
```

### 3.2 MLFQ实现

**数据结构**：

```c
#define MLFQ_LEVELS 5

/* MLFQ调度器 */
struct mlfq_scheduler {
    struct {
        struct process *head;
        struct process *tail;
        uint32_t time_slice;      /* 该级别的时间片 */
        uint32_t process_count;
    } levels[MLFQ_LEVELS];
    
    uint64_t boost_time;          /* 上次提升时间 */
    uint64_t boost_interval;      /* 提升间隔（防止饿死） */
};

/* 初始化MLFQ */
void mlfq_init(void)
{
    for (int i = 0; i < MLFQ_LEVELS; i++) {
        levels[i].head = NULL;
        levels[i].tail = NULL;
        levels[i].time_slice = 8 * (1 << i);  /* 8, 16, 32, 64, 128ms */
        levels[i].process_count = 0;
    }
    
    boost_interval = 1000;  /* 每1000个tick提升一次 */
    boost_time = timer_get_ticks();
}
```

**调度逻辑**：

```c
void mlfq_schedule(void)
{
    /* 周期性提升所有进程（防止饿死） */
    if (timer_get_ticks() - boost_time > boost_interval) {
        mlfq_boost_all();
        boost_time = timer_get_ticks();
    }
    
    struct process *prev = current;
    struct process *next = mlfq_pick_next();
    
    if (!next) {
        next = idle_process;
    }
    
    /* 处理当前进程 */
    if (prev && prev->state == PROCESS_STATE_RUNNING) {
        if (prev->time_slice_remaining == 0) {
            /* 用完时间片，降级 */
            int level = prev->mlfq_level;
            if (level < MLFQ_LEVELS - 1) {
                prev->mlfq_level++;
            }
            mlfq_add_process(prev);
        } else {
            /* 主动让出或被阻塞，保持优先级 */
            mlfq_add_process(prev);
        }
    }
    
    /* 设置新进程的时间片 */
    next->time_slice = levels[next->mlfq_level].time_slice;
    next->time_slice_remaining = next->time_slice;
    
    context_switch(prev, next);
}
```

## 🏗️ 第4部分：实时调度

### 4.1 实时调度的需求

**什么是实时系统？**

```
硬实时系统（Hard Real-Time）：
- 任务必须在截止期限内完成
- 错过截止期限 = 系统失败
- 例子：飞行控制系统、心脏起搏器

软实时系统（Soft Real-Time）：
- 任务应该尽快完成
- 错过截止期限 = 性能下降
- 例子：视频播放、游戏
```

**实时调度的特点**：

```c
/* 实时进程特点 */
1. 固定优先级（不动态调整）
2. 抢占式调度（高优先级可以抢占低优先级）
3. 优先级范围：0-99（数字越小越高）
4. 不与普通进程竞争（实时优先级 > 普通优先级）
```

### 4.2 SCHED_FIFO（实时FIFO）

**规则**：

```
1. 最高优先级的就绪进程获得CPU
2. 进程一直运行，直到：
   - 主动让出CPU（yield或I/O阻塞）
   - 被更高优先级进程抢占
   - 终止
3. 同优先级进程按FIFO顺序排队
4. 没有时间片限制
```

**实现**：

```c
struct process *sched_fifo_pick_next(void)
{
    /* 扫描实时优先级（0-99） */
    for (int pri = 0; pri < 100; pri++) {
        if (rt_queues[pri]) {
            struct process *next = rt_queues[pri];
            /* FIFO：从头部取，不移除（继续运行） */
            return next;
        }
    }
    
    /* 没有实时进程，调度普通进程 */
    return normal_pick_next();
}

/* FIFO进程只有主动让出才会切换 */
void sched_fifo_yield(struct process *proc)
{
    /* 移到队列尾部 */
    rt_queues[proc->rt_priority] = proc->next;
    append_to_queue(proc, proc->rt_priority);
}
```

### 4.3 SCHED_RR（实时轮转）

**规则**：

```
类似SCHED_FIFO，但有时间片：
1. 最高优先级的就绪进程获得CPU
2. 进程运行一个时间片（默认100ms）
3. 时间片用完后，移到队列尾部
4. 同优先级进程轮转
```

**实现**：

```c
#define RT_TIMESLICE 100  /* 100ms时间片 */

void sched_rr_tick(struct process *proc)
{
    if (proc->policy != SCHED_RR) {
        return;
    }
    
    proc->time_slice_remaining--;
    
    if (proc->time_slice_remaining == 0) {
        /* 时间片用完，轮转 */
        proc->time_slice_remaining = RT_TIMESLICE;
        
        /* 移到队列尾部 */
        int pri = proc->rt_priority;
        rt_queues[pri] = proc->next;
        append_to_queue(proc, pri);
        
        /* 触发调度 */
        schedule();
    }
}
```

## 🏗️ 第5部分：CFS（完全公平调度器）

### 5.1 CFS原理

**Linux CFS的核心思想**：

```
传统调度器：维护队列，按顺序调度
CFS：维护红黑树，按虚拟运行时间调度

核心概念：
1. 虚拟运行时间（vruntime）
2. 权重（weight，基于nice值）
3. 红黑树（高效的平衡二叉搜索树）
```

**虚拟运行时间**：

```c
/* 虚拟运行时间 = 实际运行时间 × (1024 / weight) */

进程A: nice=0,  weight=1024, 实际运行10ms
vruntime_A = 10 × (1024/1024) = 10

进程B: nice=-10, weight=3121, 实际运行10ms
vruntime_B = 10 × (1024/3121) = 3.28  ← 更低！

进程C: nice=+10, weight=335, 实际运行10ms
vruntime_C = 10 × (1024/335) = 30.6   ← 更高！

结论：
- nice值越低（优先级越高），vruntime增长越慢
- vruntime越小的进程越应该被调度
- 实现了"完全公平"：所有进程的vruntime趋于相等
```

**红黑树调度**：

```
红黑树（按vruntime排序）：

            [P3, vtime=50]
           /              \
    [P1, vtime=30]    [P5, vtime=80]
         /                    \
   [P2, vtime=20]         [P6, vtime=90]

调度规则：
1. 选择最左边的节点（vruntime最小）
2. 运行一段时间后，更新vruntime
3. 重新插入树中
4. 重复
```

### 5.2 CFS简化实现

由于红黑树实现复杂，我们使用**排序链表**作为简化版本：

```c
/* CFS调度实体 */
struct sched_entity {
    uint64_t vruntime;           /* 虚拟运行时间 */
    uint64_t exec_start;         /* 本次执行开始时间 */
    uint64_t sum_exec_runtime;   /* 累计执行时间 */
    int weight;                  /* 权重 */
};

/* Nice值到权重的映射表 */
static const int nice_to_weight[40] = {
    /* nice -20 到 -1 */
    88761, 71755, 56483, 46273, 36291,
    29154, 23254, 18705, 14949, 11916,
    9548, 7620, 6100, 4904, 3906,
    3121, 2501, 1991, 1586, 1277,
    /* nice 0 */
    1024,
    /* nice 1 到 19 */
    820, 655, 526, 423, 335,
    272, 215, 172, 137, 110,
    87, 70, 56, 45, 36,
    29, 23, 18, 15, 12
};

/* 计算权重 */
int calc_weight(int nice)
{
    return nice_to_weight[nice + 20];  /* nice范围：-20到+19 */
}

/* 更新vruntime */
void update_vruntime(struct process *proc, uint64_t delta_exec)
{
    /* vruntime += delta_exec × (1024 / weight) */
    proc->se.vruntime += (delta_exec * 1024) / proc->se.weight;
}

/* 选择下一个进程（vruntime最小的） */
struct process *cfs_pick_next(void)
{
    struct process *leftmost = NULL;
    uint64_t min_vruntime = UINT64_MAX;
    
    /* 遍历所有就绪进程，找到vruntime最小的 */
    struct process *proc = ready_queue_head;
    while (proc) {
        if (proc->se.vruntime < min_vruntime) {
            min_vruntime = proc->se.vruntime;
            leftmost = proc;
        }
        proc = proc->next;
    }
    
    return leftmost;
}
```

## 🏗️ 第6部分：统一调度框架

### 6.1 调度类（Scheduling Class）

**Linux风格的调度类架构**：

```c
/* 调度类操作 */
struct sched_class {
    /* 将进程加入就绪队列 */
    void (*enqueue_process)(struct process *proc);
    
    /* 从就绪队列移除进程 */
    void (*dequeue_process)(struct process *proc);
    
    /* 选择下一个要运行的进程 */

    /* 定时器tick处理 */

    /* 进程让出CPU */
    void (*yield)(struct process *proc);
};

/* 实时调度类 */
const struct sched_class rt_sched_class = {
    .enqueue_process = rt_enqueue,
    .dequeue_process = rt_dequeue,
    .pick_next = rt_pick_next,
    .tick = rt_tick,
    .yield = rt_yield,
};

/* CFS调度类 */
const struct sched_class fair_sched_class = {
    .enqueue_process = cfs_enqueue,
    .dequeue_process = cfs_dequeue,
    .pick_next = cfs_pick_next,
    .tick = cfs_tick,
    .yield = cfs_yield,
};

/* 空闲调度类 */
const struct sched_class idle_sched_class = {
    .enqueue_process = idle_enqueue,
    .dequeue_process = idle_dequeue,
    .pick_next = idle_pick_next,
    .tick = NULL,
    .yield = NULL,
};
```

### 6.2 统一调度接口

```c
/* 统一调度接口 */
void schedule(void)
{
    struct process *prev = current;
    struct process *next = NULL;
    
    /* 按优先级顺序尝试各个调度类 */
    const struct sched_class *classes[] = {
        &rt_sched_class,      /* 实时优先 */
        &fair_sched_class,    /* 普通进程 */
        &idle_sched_class,    /* 空闲 */
        NULL
    };
    
    for (int i = 0; classes[i]; i++) {
        next = classes[i]->pick_next();
        if (next) {
            break;
        }
    }
    
    if (!next) {
        panic("No process to schedule");
    }
    
    /* 处理当前进程 */
    if (prev && prev->state == PROCESS_STATE_RUNNING) {
        prev->sched_class->dequeue_process(prev);
        prev->state = PROCESS_STATE_READY;
        prev->sched_class->enqueue_process(prev);
    }
    
    /* 切换到新进程 */
    next->state = PROCESS_STATE_RUNNING;
    current = next;
    
    context_switch(prev, next);
}
```
